# 人形機器人 PS4 遙控改裝教學

把原本的 Kondo 遙控器換成 PS4 手把。

```
PS4 手把 ──藍牙──> ESP32 ──UART(TX→pin 8)──> Arduino Micro ──Serial1(500000)──> 伺服馬達
```

## 資料夾說明

| 資料夾 | 用途 |
|---|---|
| `Micro_Robot/` | 燒錄到 **Arduino Micro** 的主程式(已整理) |
| `ESP32_PS4_Bridge/` | 燒錄到 **ESP32**,讀 PS4 手把並送給 Micro |
| `ESP32_GetMAC/` | 一次性小工具:查 ESP32 的藍牙 MAC |
| `Tools_MotorAdj/` | 原本的馬達調整工具(電腦端,需要 Java) |

### Micro_Robot 內的檔案
| 檔案 | 作用 | 要不要改 |
|---|---|---|
| `custom.ino` | **按鍵 → 動作**、**搖桿 → 動作**對照表 | 想改動作就改這裡 |
| `motor.h` | 所有動作幀資料(由 MotorAdj 產生) | 用 MotorAdj 產生,不要手改 |
| `pad.ino` / `pad.h` | 從 ESP32 收按鍵與搖桿、按鍵位元定義 | 一般不用改 |
| `Micro_Robot.ino` | 馬達通訊、電腦通訊協定 | 一般不用改 |
| `imu.ino` | BNO055 傾斜感測(自己寫的精簡 I2C,SDA = D2、SCL = D3);角度、持續時間、方向正負號的設定在檔案最上面 | 感測器方向反了才改 |
| `custom.h` | 函式宣告 | 不用改 |

整理內容:移除所有 Kondo 專用程式、I2C 手把、感測器、計時器與永遠不會執行的 `mode 2`,Micro 程式佔用 77%(加入搖桿功能後;再省空間的最大一塊是 `motor.h` 的動作幀資料,約 11.5 KB,只能靠減少幀數)。`custom.ino` 加上中文註解,動作邏輯與原本相同。

---

## 第 0 步:確認硬體

- **M5Stack ATOM Lite**(ESP32-PICO-D4,有傳統藍牙,可配對 PS4 手把)。
- Arduino Micro 已經在你的電路板上。
- 三條線:

| ATOM Lite | 你的電路板 (PCB X1 mini) |
|---|---|
| Grove 接頭的 **G26**(看 Grove 線的顏色:通常白線 = G26,黃線 = G32,請用三用電表或對照 M5Stack 官方圖確認) | **DIO 排針的 D8** |
| GND | DIO 排針的 GND(**一定要共地**) |
| 5V | DIO 排針的 5V(給 ESP32 供電;若電流不夠或不穩,改用 USB 另外供電) |

Micro 不需要回傳資料給 ESP32,所以 ESP32 的 RX 不用接。
請**不要**使用板子的 4 pin「UART 接頭」,它是 Micro 的硬體 Serial1,已被伺服馬達通訊佔用。原本 Kondo 接收器用的 D8、D9、D4 在 DIO 排針上,現在空出來了。

## 第 1 步:安裝軟體

1. 安裝 **Arduino IDE 1.8.19** 或 **2.x**(arduino.cc/en/software;1.8.19 在下方 Legacy IDE,選 ZIP 解壓縮即可,可與舊版並存)。舊的 1.8.4 不建議,裝不了 ESP32 套件。
2. ESP32 支援:「檔案 → 偏好設定 → 額外的開發板管理員網址」加入
   `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
   然後「工具 → 開發板 → 開發板管理員」搜尋 **esp32** 安裝 **2.0.17**(**不要用 3.x**,PS4 函式庫在 3.x 上有問題)。
3. 安裝 PS4Controller 函式庫:到 `github.com/aed3/PS4-esp32`,下載 ZIP,
   「草稿碼 → 匯入程式庫 → 加入 .ZIP 程式庫」。
4. Micro 這邊不需要額外函式庫(舊的 `IcsSoftSerialClass` 已移除),`SoftwareSerial` 是內建的。

## 第 2 步:查 ESP32 的藍牙 MAC

1. 開啟 `ESP32_GetMAC/ESP32_GetMAC.ino`。
2. 工具 → 開發板選 **M5Stack-ATOM**,選好 COM 埠,上傳。
3. 開啟序列埠監控視窗(115200),記下 `ESP32 Bluetooth MAC: xx:xx:xx:xx:xx:xx`。

## 第 3 步:讓 PS4 手把記住 ESP32

PS4 手把只會連到它記住的「主機」。要把 ESP32 的 MAC 寫進手把:

1. 下載 **SixaxisPairTool**(Windows 小工具;網路上搜尋即可,安裝驅動時請留意來源)。
2. 用 USB 線把 PS4 手把接上電腦,開啟工具。
3. 在 Master 欄輸入第 2 步的 MAC,按 **Update**。
4. 拔掉線。

## 第 4 步:燒錄 ESP32 橋接程式

1. 開啟 `ESP32_PS4_Bridge/ESP32_PS4_Bridge.ino`。
2. 把 `#define PS4_MAC "aa:bb:cc:dd:ee:ff"` 改成你的 MAC。
3. 開發板選 **M5Stack-ATOM**,上傳。
4. 開序列埠監控視窗,按手把中間的 **PS 鍵**,手把燈會變成穩定亮。按按鍵時會看到 `key=0x.... stickBtn=0x..`(一般按鍵與 L3/R3 分開顯示)。

> 若沒有連上:確認 MAC 一致、手把電量足夠、Arduino core 是 2.0.x。

## 第 5 步:燒錄 Micro

1. 開啟 `Micro_Robot/Micro_Robot.ino`。
2. 開發板選 **Arduino Micro**,選好 COM 埠,上傳。
   (Micro 的 pin 0/1 是硬體 Serial1,和 USB 分開,上傳時不需要拔線。)
3. 接好第 0 步的三條線。
4. 開 Micro 的序列埠監控視窗(115200),手把連線後每 200 ms 會印一行,例如:
   `key=0x1 LX=0 LY=95 RX=-3 RY=0 L3=0 R3=0`
   用來確認按鍵、搖桿、L3/R3 的數值都正確。要關閉,把 `pad.h` 的 `PAD_DEBUG_PRINT` 改成 0。
   (接上電腦用 MotorAdj 時不會印,不影響它。)

## 第 6 步:操作

1. 機器人上電,ESP32 與 Micro 都會開機。
2. 按 PS 鍵讓手把連線。
3. 按 **Options** = START,機器人進入遙控模式並回站姿。
4. 按鍵對照:

| PS4 | 原 Kondo | 動作 |
|---|---|---|
| ↑ | UP | 前進 |
| ↓ | DOWN | 後退 |
| → / ← | RIGHT / LEFT | 右轉 / 左轉 |
| ✕ | CROSS | 幀 35→36 |
| ○ | CIRCLE | 幀 23→24 |
| □ | SQUARE | 幀 25→26 |
| L1 / R1 | L1 / R1 | 幀 29→30 / 27→28 |
| L2 / R2 | L2 / R2 | 單純的轉身(一個 do while)。「推左搖桿左 / 右的途中再按 L2 或 R2」的組合動作在左搖桿那一段(現在是註解的空位) |
| **Options** | START | 開始 / 回站姿 |
| **Share** | STOP | 馬達全部放鬆 |

按住方向鍵會持續走,放開會自動回站姿。

蘑菇頭(搖桿)、L3/R3、L2/R2 搭配搖桿的動作目前**都是註解,尚未綁定**(範例在 `custom.ino`),見第 7 步。

安全機制:ESP32 與 Micro 之間超過 0.3 秒沒收到資料,Micro 會當作「沒有按鍵」,動作會停止。手把斷線也是同樣情形。

## 第 7 步:修改 / 新增動作

- **改動作姿勢**:雙擊 `Tools_MotorAdj/MotorAdjPlus.jar`(咖啡杯圖示,需安裝 Java)。它就是原本的 MotorAdj,只是在「馬達參數」分頁、「轉換設定」按鈕正下方多了一顆 **「更新到機器人(燒錄)」**:
  1. 照平常調整動作,按「轉換設定」輸出 `motor.h`(存在 `Tools_MotorAdj` 資料夾,或直接選存到 `Micro_Robot\motor.h` 都可以)。
  2. 按「更新到機器人(燒錄)」。它會自動:中斷串口連線 → 備份舊的 `motor.h` 並複製新的 → 編譯 → 燒錄到 Arduino Micro,過程顯示在跳出的小視窗。
  3. 看到「完成」後,按 MotorAdj 的「串口連接」重新連線,繼續調整。
  - MotorAdj 不用關,可以一直開著。原本的 `MotorAdj_release.jar` 沒有修改,仍可照舊使用。
  - 只有 `Tools_MotorAdj\motor.h` 比 `Micro_Robot\motor.h` 新時才會複製,所以直接輸出到 `Micro_Robot` 的不會被蓋掉。
  - 不開 MotorAdj、只想把目前的 `motor.h` 燒進去時,可以雙擊 `一鍵更新動作.bat`。
  - 外掛的原始碼在 `Tools_MotorAdj/MotorAdjPlus_src/Plus.java`。
  - `MotorAdjPlus` 另外修正了「關閉馬達」:按下去只會把馬達關閉(畫面也顯示成關閉),**不會把「關閉」寫進該幀的資料**。之後按「讀出」,就會把該幀原本的設定讀回來並恢復動作。(只有用 `MotorAdjPlus.jar` 開啟才有這個修正,原本的 `MotorAdj_release.jar` 仍是舊行為。)
  - **「動作程式」分頁(在「馬達偏移量」旁邊):直接改 Arduino 的動作與延遲時間。**
    1. 切到「動作程式」分頁,上方的下拉選單會列出 `custom.ino` 裡每個 `switch` 的每個 `case`(按鍵、按下搖桿 L3/R3、左搖桿方向、右搖桿方向),例如「按鍵 › case PAD_BTN_UP」。
    2. 選一個,下面就會顯示**從 `case` 到結尾的整段程式**,可以直接改(例如把 `SetFrameRun(2, 100)` 的 100 改成別的延遲時間)。改過的項目前面會有 ●。
    3. 改完按「更新到機器人(燒錄)」(這個分頁和「馬達參數」分頁各有一顆,功能相同)。它會:把修改寫回 `Micro_Robot\custom.ino`(舊版先備份到 `backup`)→ 編譯 → 燒錄。
    4. 如果**編譯失敗**,`custom.ino` 會自動還原成修改前的樣子,你的修改還留在分頁裡,修正後再按一次即可。
    - 「重新載入 custom.ino」:重新讀檔(也會放棄還沒寫入的修改);「還原這一段」:把目前這段改回檔案裡的原樣。
    - 這裡只能改 `case` 內的內容;`case` 之外的程式(例如迴圈最後的 `delay(10)`)要直接改 `custom.ino`。
    - 同一時間可以改好幾段,一起按一次更新就會全部寫入。
  - **「路徑設定…」按鈕**(「馬達參數」分頁、「載入設定」正下方;「動作程式」分頁最上面一列也有):可以設定
    1. **Arduino 程式資料夾**(裡面有 `custom.ino`、`motor.h`)
    2. **motor.h 來源**(MotorAdj 輸出的那個檔)
    3. **arduino-cli 位置**
    4. **序列埠**(留空 = 自動偵測 Arduino Micro;有多塊板子時可以指定,例如 `COM7`)

    欄位**預設是空白,空白 = 自動**(依資料夾位置推算),視窗下方會顯示目前實際使用的位置。按「儲存」後設定會存在 `Tools_MotorAdj/MotorAdjPlus.properties`,下次開啟自動套用,不用每次重設。「還原預設」會把欄位清成空白。
  - **沒有變動就不上傳:** 每次成功上傳後,會記住當時程式資料夾(`custom.ino`、`motor.h` 等)的內容指紋(存在 `MotorAdjPlus.properties` 的 `lastUpload`)。下次按「更新到機器人」時,如果內容和上次上傳的一樣,就直接略過編譯與上傳,只顯示「沒有變動,不用重新上傳」(這種情況視窗不會自動關閉;只有上傳成功時才會自動關閉)。**要強制重新上傳:按住 Shift 再按按鈕。**(換了一塊板子、或用別的方式燒錄過時,請用 Shift 強制上傳一次。)
  - **鏡像功能(左右對稱的動作):**
    1. 到「**鏡像**」分頁(最右邊),按「新增配對」,設定哪兩顆馬達左右鏡像。每一列有:**啟用**、**馬達 A**、**馬達 B**(編號 = 畫面上的 Ch 編號)、**方向**、**模式**。設定會自動存起來(`MotorAdjPlus.properties`),下次開啟還在。
       - **方向:** 同向 = 位置照抄;反向 = 以 1500 為中心反轉(新位置 = 3000 − 對方的位置)。偏掉的部分用「馬達偏移量」調整。
       - **模式:** 互換 = A、B 對調;A→B = 只有 B 變成 A 的鏡像;B→A = 只有 A 變成 B 的鏡像。啟用與時間(速度)會一起帶過去。
       - **單顆自己鏡像:** A、B 選同一顆、方向選「反向」,這一顆會自己左右反轉。
    2. 到「馬達參數」分頁,先「讀出」你要鏡像的那一幀,按左下角的 **「鏡像(畫面)」** 按鈕。畫面上這一幀的參數(連機器人連著時馬達也會動)就會依設定變成鏡像。
    3. **不會寫入。** 滿意的話,自己輸入要存的幀編號,再按原本的「寫入」。不滿意就再按「讀出」還原。
    - 同一顆馬達不要出現在兩組啟用的配對裡(會提示並且不做任何修改)。鏡像後的位置會被限制在馬達位置的最小、最大值之內。
  - **外觀:** MotorAdjPlus 預設用現代扁平風格(圓角按鈕、藍色重點色,「開啟馬達」為綠色、「關閉馬達」為紅色)。在「路徑設定…」視窗最下面的「**外觀**」可以切換 **淺色(預設) / 深色 / 原本的樣子**,按「儲存」立刻生效並記住。外觀用的是 [FlatLaf](https://www.formdev.com/flatlaf/)(Apache 2.0 授權),檔案在 `Tools_MotorAdj/MotorAdjPlus_lib/flatlaf-3.7.2.jar`;這個檔案被刪掉的話,會自動維持原本的外觀,不影響功能。
    - **科技風(新):** 在「設定」分頁的「背景…」下面有「**外觀**」下拉選單,現在有 4 種:**淺色(預設)/ 深色 / 科技風 / 原本的樣子**,選了馬上換並記住。**科技風**是深藍黑底、青色霓虹重點色(捲軸、-/+ 按鈕、分頁底線、用量長條)、數字用等寬字型(像儀表板讀數),背景有細網格、角落光暈和四個角的青色邊框;「開啟馬達」「關閉馬達」變成霓虹綠和霓虹紅。**原本的淺色、深色外觀完全保留**,隨時可以切回去。
    - **科技風會強制使用內建的科技風背景**,不管有沒有設自訂背景。你在「背景…」設定的圖片和純色**會保留**(不會被刪掉),切到「淺色 / 深色 / 原本的樣子」時就會再顯示。在科技風外觀下開「背景…」視窗,上方會有橘色提示說明這件事。
    - 想連同程式一起回到加入科技風之前的版本,git 有標記 `ui-v1`(`git checkout ui-v1`)。
  - **自訂背景:** 到「**設定**」分頁(串口連接那一頁),左下方的 **「背景…」** 按鈕。把 **JPG / PNG / GIF / BMP 圖片直接拖進**跳出的視窗,或按「選擇圖片…」,上方會**即時預覽**,同時主視窗也會跟著變。
    - **圖片遮罩**滑桿:越高圖片越淡、文字越清楚(預設 75%);0% = 完全看到圖片。圖片會自動放大蓋滿整個視窗。
    - 也可以只選**純色**背景(「選擇純色…」)。「清除圖片 / 清除純色」可以拿掉。
    - 按「確定」才會儲存並記住;按「取消」或關閉視窗會還原成開啟前的樣子。
    - 選到的圖片會**複製一份**到 `Tools_MotorAdj/background` 資料夾,原檔之後刪掉、搬走都不會影響背景。換圖、清除時舊的副本會自動刪掉。
    - 背景可以跟淺色 / 深色外觀搭配,遮罩會跟著外觀換顏色。
    - **圖片比例不同怎麼辦:** 「背景設定」視窗裡有 **顯示方式**:**蓋滿視窗**(預設,會裁掉多出來的部分)、**完整顯示**(整張都看得到,兩側或上下會留邊,留邊顏色用「選擇純色」設定)、**拉伸填滿**(會變形)。另外有 **縮放**(100~300%)、**水平位置**、**垂直位置** 滑桿,也可以**直接在預覽上用滑鼠拖曳**移動圖片、**滾輪縮放**,決定要留圖片的哪一塊。換新圖時位置與縮放會自動回到預設;「重設位置與縮放」可以手動回到預設。
  - **馬達捲軸微調:** 「馬達參數」分頁每顆馬達的捲軸,**左右兩端各有一顆「-」「+」按鈕**,按一下 **±10**,**按住不放會連續移動**;**點捲軸中間的空白軌道一次 ±100**。這兩個數字可以在畫面左側的「捲軸微調」修改(「-」「+」按鈕:± 1 / 5 / 10 / 20 / 30;點空白軌道:± 10 / 20 / 30 / 50 / 100 / 200),會記住。馬達沒啟用(捲軸是灰色)時,按鈕也是灰色、按不動。
  - **每顆馬達各自的位置範圍(「各馬達範圍…」):** 「馬達參數」分頁左下角、「鏡像(畫面)」旁邊有一顆 **「各馬達範圍…」**,可以替**每一顆馬達**單獨設定最小 / 最大位置(數字跟主畫面一樣,中心是 0)。**預設是「設定」分頁的 ±900**,沒改過的馬達就是預設。設好之後,這顆馬達的**捲軸、「-」「+」按鈕、直接輸入數字、鏡像**都不會超出它的範圍(捲軸上停一下會顯示「這顆的範圍 …」)。
    - **用人偶模式量極限:** 在「各馬達範圍」視窗點**編號旁邊的圈圈**,那一顆就進入人偶模式(放鬆;還沒進人偶模式會自動進入),用手把它擺到**最小的位置**,按 **「最小 ← 目前位置」**;再擺到**最大的位置**,按 **「最大 ← 目前位置」**。視窗裡的「目前位置」會即時更新。**人偶模式裡不限制範圍**,才能擺到極限;離開人偶模式後限制才生效。
    - 也可以**直接改表格**的數字;「這顆還原預設」「全部還原預設」可以回到 ±900。範圍不會超過「設定」分頁的全域範圍(想要更大請先改全域)。
    - **「檢查所有幀」:** 如果有些幀的舊資料已經超出新設的範圍,按這顆會列出來,並可以一次壓回範圍內(只改畫面上的資料,之後要「儲存設定」或「更新到機器人」才會存下來)。
    - 範圍存在 `MotorAdjPlus.properties`(`limit.1` ~ `limit.26`),**不會改你的 .config 檔**。
  - **復原 / 重做「寫入」:** 「馬達參數」分頁「寫入」按鈕旁邊有 **「← 復原」** 和 **「重做 →」**。每次按「寫入」之前,MotorAdjPlus 會先把那一幀目前存的內容記下來。不小心按到「寫入」時,按「← 復原」就會把那一幀**還原成寫入之前的樣子**(畫面也會切到那一幀);復原之後又後悔,按「重做 →」可以**再往前**回到剛才的內容。可以連續來回多次(最多記 100 次);做了新的「寫入」之後,「重做」會清空(跟一般的復原重做一樣)。沒有可復原或可重做的內容時,按鈕是灰色的。注意:紀錄只存在記憶體,**關掉 MotorAdj 就清空**;只處理「寫入」,不包含「儲存設定」等其他動作。
  - **人偶模式(用手擺姿勢、自動讀角度):** 按「馬達參數」分頁的「人偶模式」,每顆馬達旁邊會出現一個**圓點**。選一顆,那顆就是「人偶」(放鬆中,可以用手擺),畫面上它的數值會即時更新成實際角度;選下一顆,前一顆會鎖在你擺好的位置。全部擺好後,輸入幀編號按「寫入」存成一幀;再按一次「人偶模式」離開。
    - **MotorAdjPlus 修正了畫面:** 原本一按「人偶模式」,所有馬達的勾選框會被取消、捲軸整排變灰,看起來像「全部放電」,但**實際上並沒有送任何指令給機器人**(馬達還有力)。現在進入人偶模式時會**維持原本的勾選與藍色捲軸**,並把**被選為人偶(放鬆中)的那顆馬達的勾選框標成橘色**,一眼看出現在哪顆是軟的。(只有用 `MotorAdjPlus.jar` 開啟才有這個修正。)
    - **離開人偶模式時**,MotorAdj 會把「畫面上記錄的姿勢」整組重新送給機器人,所以機器人會回到畫面資料的姿勢,不一定是你用手擺的姿勢。想保留手擺的姿勢,**離開之前先「寫入」成一幀**。
    - 使用時請先扶好機器人(或讓它躺著、架空),被選到的那顆會放鬆,可能因為重力下垂。
  - **啟動時最大化、內容等比例放大並置中:** 打開 MotorAdj 時視窗會**自動放到最大**。「設定」「馬達參數」「馬達偏移量」三頁的版面是固定座標,原本不會跟著視窗放大,所以 MotorAdjPlus 在視窗變大時,把裡面每個元件的**位置、大小、字體一起乘上同一個倍率**(比例不變、不會拉長變形),整個畫面放在視窗**正中央**。視窗縮回原本大小時,畫面跟以前一模一樣(倍率 1)。倍率最小 1、最大 3。「動作程式」「鏡像」兩頁本來就會跟著視窗大小。勾選框、單選圈這類固定大小的小圖示不會跟著放大。想關掉自動最大化:在 `MotorAdjPlus.properties` 加一行 `startMaximized=0`;只想置中、不要放大:加 `autoScale=0`。
- **介面字體:** 預設用「**Noto Sans TC**」(思源黑體,比微軟正黑體粗一點);電腦沒裝時退回「微軟正黑體 UI」。想換別的字體:在 `MotorAdjPlus.properties` 加一行 `fontName=字體名稱`,例如 `fontName=Microsoft JhengHei UI`(原本的)、`fontName=Microsoft JhengHei UI Light`(比較細)、`fontName=Microsoft YaHei UI`(微軟雅黑,也比較粗)。**注意:** Java 只看得到字體家族名稱,看不到「Medium」「Light」這類粗細版本(例如 `Noto Sans TC Medium` 會被當成不存在,退回內建字體),所以請用家族名稱。字體名稱寫錯會變成預設字體。
  - **快速新增幀:** 「馬達參數」分頁**左下角**(「捲軸微調」的上方)有一顆 **「+ 新增幀(60/90)」**(括號是目前幀數 / 上限)。按一下,在最後多一幀,內容**複製畫面上目前這一幀**,並自動切到那一幀讓你編輯(改完按「寫入」)。
    - 新增後要記得 **「儲存設定」**(幀數會存進設定檔的 `mmax`)和 **「轉換設定」**(輸出新的 `motor.h`),然後按「更新到機器人」。
    - **Arduino 程式不用改**:`motor.h` 裡的 `MOTOR_FRAME_MAX` 會自動跟著變(用 MotorAdj 實際輸出的 65 幀 `motor.h` 放進去編譯驗證過)。
    - **限制是 Micro 的程式空間:** 每幀約佔 156 位元組。75 幀加上傾斜感測(BNO055)約 86%;加到 90 幀約 94%,還剩約 1.6 KB 給你之後寫的呼叫與邏輯(把 `pad.h` 的 `PAD_DEBUG_PRINT` 關掉可再多約 1 KB)。超過約 110 幀就放不下,所以**幀數上限預設 90**,超過時會先警告。上限可以在 `MotorAdjPlus.properties` 加一行 `frameLimit=100` 修改(要先確認空間夠)。
- **檢查語法(不燒錄):** 「動作程式」分頁底部有一顆 **「檢查語法(不燒錄)」**。按下去只會**編譯、不燒錄**,也**不會改你的 custom.ino**:它把「動作程式」分頁裡**還沒寫入**的修改套進暫存的複本再編譯(motor.h 如果 Tools_MotorAdj 裡的比較新,也用比較新的)。通過會顯示「編譯通過」和程式空間用量;失敗會列出**第幾行、那一行的內容、錯誤原因**,常見錯誤(少分號、少括號、名稱拼錯、參數數量不對、全形符號…)會附中文提示。第一次檢查約 20~40 秒,之後比較快。**通過只代表語法正確**,動作對不對、幀編號是不是你要的,要燒進機器人實測;幀編號是否存在,看分頁下方「幀編號」那一行。行號是整份 custom.ino 的行號。(「更新到機器人」本來就會先編譯、失敗就不燒錄,並還原 custom.ino;這顆是讓你燒錄前先檢查。)
  - **現有 case 的最外層迴圈已經統一改成「這個 case 的按鍵還按著」:** `custom.ino` 裡每個 case 最外層的 `do … while (…)`,條件都改成只看這個 case 自己的按鍵,**按著別的鍵也不會跳出去**,放開這個 case 的鍵才結束:
    - 按鍵(前進、左轉、右轉、×、○、□、R1、L1、L2、R2)→ `while (keyHas(PAD_BTN_X))`
    - L3 / R3 → `while ((pad_getStickButtons() & PAD_L3) && pad_getKey() != PAD_BTN_STOP)`
    - 左 / 右搖桿方向 → `while (LS_DIR == DIR_UP && pad_getKey() != PAD_BTN_STOP)`
    - **搖桿類的條件多了 `pad_getKey() != PAD_BTN_STOP`:** 不然推著搖桿時按 Share 會沒反應。按鍵類的 `keyHas()` 本身已經排除了 Share。
    - **沒改的:** 「後退」(`PAD_BTN_DOWN`),它靠「只按著後退」判斷收尾動作(`jumpFlag`),改了會變行為。Share、Options 本身也沒有迴圈。
    - **行為上的差別:** 以前按著前進再按別的鍵,迴圈條件是「有按任何鍵」,放開前進、還按著別的鍵時還會繼續走;現在放開前進就停,馬上換成另一個鍵的動作。推著搖桿時按別的按鍵,也不會再跳去那個按鍵的動作。
    - 原本的檔案備份在 `backup/custom.ino.bak_…`。
  - **方塊編輯(拖方塊,像 Scratch):** 「動作程式」分頁上方的 **「方塊編輯」** 會開啟方塊編輯器,用拖的方式編輯**目前這一段**(一個 `case`),程式碼自動產生:
    - **左邊是方塊選單,中間是你的動作(從上到下依序執行),下面即時顯示產生的程式碼。**
    - **方塊種類:** 動作(播放一幀)、等待、放鬆全部馬達、**重複(`do while`)**、**如果 / 如果…否則(`if else`)**、**組合鍵**(如果 有按著 ○ □ △ × L1 R1 L2 R2 方向鍵…)、註解、**自訂程式碼**(自己寫 C++,原樣放進去)。
    - **拖曳:** 從左邊拖新方塊進中間;拖中間的方塊可以移動(放進 `重複` / `如果` / `否則` 裡面也行);**拖回左邊 = 刪除**;雙擊左邊的方塊 = 加到最後面;右鍵有「刪除、停用(變註解)、複製」。「復原 / 重做」按鈕可以反悔。
    - **條件可以自己組:** `重複` 和 `如果` 的條件可以選「沒有按任何鍵、有按著、只按著、沒按鍵或只按…、搖桿按壓(L3/R3)、左 / 右搖桿的方向、自訂條件」,可以加「不是」,用「而且 / 或」接起來,「+ 條件」增加。
    - **用語預設是英文,可以切換:** 方塊上的邏輯用語預設用英文(`AND / OR / NOT`、`repeat while`、`if … then`、`else`、`no button pressed`、`any button pressed`、`holding`、`only holding`、`none, or only`、`stick press`、`left stick direction is`…),比中文「而且 / 不是 / 沒有按任何鍵」好懂。視窗右下角的 **「English → 中文」** 按鈕可以切換成中文,會記住你的選擇(`MotorAdjPlus.properties` 的 `blockLang`)。滑鼠停在條件的下拉選單上,會顯示那個條件的**中文說明**。
    - **方塊畫成程式碼的樣子:** 方塊看起來就像原本的程式(`do {` … `} while (條件);`、`if (條件) {` … `} else {` … `}`、`SetFrameRun(幀, 時間);`),所以你認得的寫法在方塊上也認得;不同的是它們是**可以拖的彩色方塊**,幀編號、時間、備註是欄位。
    - **條件就是一行可以直接改的程式碼**(例如 `pad_getStickButtons() == PAD_L3 && pad_getKey() == 0`),改了會自動更新下面的預覽。條件旁邊的 **「插入 / insert」** 按鈕有常用條件的選單(沒有按任何鍵、有按任何鍵、有按著某個鍵、L3 / R3、搖桿有往某邊推),選了會用 `&&` 接在後面,不用背語法。**滑鼠停在條件上,會顯示這個條件的白話說明。**
    - **每個動作方塊有 「+ 組合 / + combo」按鈕:** 選一個鍵(例如 ○),這個動作會自動變成「`if (keyHas(PAD_BTN_CIRCLE))` 就播這一幀、`else` 播原本那一幀」,**外面迴圈的條件也自動更新**;你只要改新那一幀的編號。這就是「單純往左是 13、12,按著 ○ 變成 13、60」的做法。
    - **註解 / 取消註解,點一下就好:** 每個動作(`SetFrameRun`、`delay`、`uart_disableMotor`)最前面有一顆 **`//`** 小按鈕:**點一下**就在「註解掉(先不執行,方塊變淡、按鈕變橘色)」和「啟用」之間切換,不用打字、不用右鍵。
    - **最外層迴圈的條件自動填好:** 把「重複」拖進**最外層**(case 底下第一層)時,條件會自動填成**這個 case 的按鍵還按著就繼續**,同時按別的鍵也不會跳出去:
      - 按鍵的 case(例如 `case PAD_BTN_R1:`)→ `keyHas(PAD_BTN_R1)`
      - L3 / R3 → `(pad_getStickButtons() & PAD_L3)`
      - 左 / 右搖桿方向的 case(例如 `DIR_LEFT`)→ `LS_DIR == DIR_LEFT`(會自動補上 `custom_stickUpdate();`)
      - 每個「重複」結尾有一顆 **「自動填 case 按鍵」** 按鈕,隨時可以把條件換成這個。放在裡面幾層的「重複」不會自動填(通常要不同的條件)。
      - **注意:** 這樣按著 L3 時再按別的鍵,不會跳去執行那個鍵的動作(迴圈不再被別的鍵卡住)。
    - **組合鍵會自動更新邏輯:** 把「如果 有按著 ○」拖進一個 `重複` 裡面,外面的迴圈條件如果是「沒有按任何鍵」(例如 L3 的 `pad_getKey() == 0`),會**自動改成「沒按鍵,或只按 ○」**,不然一按 ○ 就跳出迴圈、組合鍵永遠進不去。(只有迴圈條件裡有「沒有按任何鍵」才會改;「有按任何鍵」的迴圈不用改。)
    - **外面的迴圈條件會自動跟上(不管你是拖方塊、按 `+ combo`、還是自己改條件文字):** 只要一個「重複」裡面有「`if` 按著某個鍵」(`keyHas(PAD_BTN_X)`),而且這個重複的條件裡有「沒有按任何鍵」(`pad_getKey() == 0`),就會自動改成「沒按鍵,或只按 X」。不然你一按 X,外面的迴圈在結尾檢查條件時就會跳出整個 case,組合永遠進不去(或只有剛好卡到時機才進得去)。編輯條件欄位、離開欄位、重畫、按「套用」時都會檢查,改了會在視窗下方提示。
    - **會卡住的只有迴圈:** `if` / `else` 只是做一次,不會卡住;`do … while` 會一直待在裡面直到條件不成立。**迴圈條件不要用「永遠成立」(例如 `1`)**,不然連 Share(全部放鬆)都出不來。
    - **幀欄位會檢查:** 填的幀編號不存在(超過 motor.h 的幀數)會變紅。
    - **按「套用到這一段」** 才會把結果放進編輯區(可以 Ctrl+Z 還原);之後照樣用「檢查語法」「更新到機器人」。
    - **限制:** 只能編輯 case 開頭的段落。打開時會把原本的程式讀成方塊、再產生回來**比對程式內容**,不一樣就不開放(避免弄壞你的程式);讀不懂的寫法會變成「自訂程式碼」方塊原樣保留。**組合是「先按 A、途中加按 B」**,同時按下的情況沒有特別處理。
    - 「有按著某個鍵」的條件會呼叫 `custom.ino` 裡的 `keyHas()` 小函式(我已經加在 `stickKeyOkForCombo` 後面),Share / Options 的特殊碼不算。
  - **自動對齊:** 「動作程式」分頁上方有一顆 **「自動對齊」**(快捷鍵 **Ctrl+Shift+F**),整理**目前正在編輯的這一段**:
    - **縮排**:依大括號 `{ }` 對齊,每層 2 個空格;`case` 底下的內容多縮一層(跟 custom.ino 原本的寫法一樣)。Tab 會換成空格、行尾多餘的空白會拿掉。
    - **行尾註解**:連續幾行的 `//` 註解對齊到同一欄(包含 `// SetFrameRun(1, 100);   // 動作 1` 這種被註解掉的程式後面的註解)。
    - **只動空白,不改程式**:整理前後,程式本身(不含空白和註解)必須完全一樣,不一樣就不會套用。`#define` 這類 `#` 開頭的行、`/* */` 區塊註解裡的內容維持原樣。
    - **Ctrl+Z 還原**(整個整理算一次,按一次就回到整理前),**Ctrl+Y** 重做。換到別的段落時,還原記錄會清掉。
  - **幀編號檢查(「動作程式」分頁底部):** 分頁底部有一行「幀編號:…」,會掃描 `custom.ino` 裡所有 `SetFrameRun(幀編號, …)`(**包含還沒寫入的修改**,被 `//` 註解掉的不算),並和 Arduino 的 `motor.h` 幀數比對:
    - **綠色**:所有編號都存在,並顯示用到幾幀、有幾幀完全沒被用到。
    - **橘色**:MotorAdj 有這一幀,但 Arduino 的 `motor.h` 還沒有 → 要先「轉換設定」,再「更新到機器人」。
    - **紅色**:這一幀不存在 → **機器人會默默忽略那個動作,不會有任何錯誤提示**,所以特別需要這個檢查。
    - 按「詳細…」會列出每個有問題的編號(在哪個 `case`),以及「完全沒被用到的幀」(例如 `0、18~22、31~34`),之後想省 Micro 空間時,就知道哪些可以刪。
  - **「設定」分頁的版面:** MotorAdjPlus 把這一頁重新排版,**用不到的「感測器」那一組(感測器編號、回傳值、開始 / 停止回傳)已隱藏**(功能還在,只是不顯示)。左邊分成三個有標題外框的區塊:**連線**(串口編號、機器型號、串口連接 / 斷開)、**馬達位置範圍**(最大值、最小值、載入 / 儲存馬達)、**外觀**(外觀選單、背景…);右邊是三張狀態卡片:
    1. **機器人狀態:** 有沒有偵測到 Arduino Micro(和序列埠)、MotorAdj 的串口有沒有連線、**程式同步狀態**(已同步 / 有尚未上傳的變更:會列出是 custom.ino、motor.h 或「動作程式」分頁的修改)、上次上傳時間、檔案修改時間。
    2. **Micro 空間用量:** 程式空間與記憶體的用量長條(用最近一次編譯的結果,按過一次「更新到機器人」後才有數字)、目前幀數,以及「加到上限幀數後」預估的空間用量與剩餘。超過 85% 變橘色、95% 變紅色。
    3. **環境檢查:** Java、arduino-cli、Arduino AVR 支援、程式資料夾、Micro 序列埠,正常是綠色、缺少是紅色並提示執行「安裝.bat」。按「重新檢查」可以重測。
    - 這個分頁顯示時才會定時更新,不會在背景一直跑。
  - **給別人用:** 把整個 `HumanoidRobot_PS4` 資料夾複製過去,先雙擊 **`安裝.bat`**。它會檢查並自動安裝:Java(用 winget)、arduino-cli(從 downloads.arduino.cc 下載,約 25 MB)、Arduino AVR 板子支援(`arduino-cli core install arduino:avr`)。已經有的會略過,需要網路。完成後雙擊 `Tools_MotorAdj/MotorAdjPlus.jar` 即可。資料夾結構不同時,用上面的「路徑設定…」指定。

  ```cpp
    break;
  ```
- 接上電腦用 MotorAdj 時,機器人會自動離開遙控模式。

### 搖桿(蘑菇頭)

**三組資料互相獨立**,互不影響:

| 組 | Micro 讀取 | 內容 |
|---|---|---|
| 一般按鍵 | `pad_getKey()` | 方向鍵、○✕□△、L1/R1/L2/R2、Options、Share |
| 推搖桿 | `pad_getStick(PAD_LX / PAD_LY / PAD_RX / PAD_RY)` | -128 ~ 127,Y 向上為正 |
| 按下搖桿 | `pad_getStickButtons()` | 回傳 `PAD_L3`、`PAD_R3`、兩個相加,或 0 |

`custom.ino` 的 `custom_stickFun()` 每圈迴圈會執行一次,裡面已經寫好範例,**動作都是註解**(`// SetFrameRun(1, 100);`),要用時把 `//` 拿掉並換成你的幀編號。組合鍵已全部移除(PS4 用不到),只保留 START、STOP。

**每支搖桿有兩組判斷**(`LS_` 開頭 = 左搖桿,`RS_` 開頭 = 右搖桿,1 = 是,0 = 不是):

| 組 | 變數 | 意思 |
|---|---|---|
| 半邊 | `LS_UP`、`LS_DOWN`、`LS_LEFT`、`LS_RIGHT` | 往那個方向推過死區就是 1。斜推時相鄰兩個會同時是 1(右上 = `LS_UP` 和 `LS_RIGHT`)。`LS_UP` 就是「上半邊」。用 `if` 判斷,R2 / L2 也用這個 |
| 單一方向 | `LS_DIR`、`RS_DIR` | 同一時間只有一個,值是 `DIR_CENTER` / `DIR_UP` / `DIR_DOWN` / `DIR_LEFT` / `DIR_RIGHT`。斜推時哪個軸推得多就算哪個。給 `switch` 用 |
| 沒推 | `LS_CENTER`、`RS_CENTER` | X、Y 都在死區內 |

死區大小用 `STICK_DEAD` 調整(預設 60,範圍 0~127,愈大愈要推多一點才算)。

**單推搖桿用 `switch (LS_DIR)`,每個方向一個 `case`,連續動作放 `do while`:**

```cpp
switch (LS_DIR) {
  case DIR_UP:
    do {
      SetFrameRun(幀A, 100);      // 動作 1
      SetFrameRun(幀B, 90);       // 動作 2
      custom_stickUpdate();       // 一定要有,不然出不來
    } while (LS_DIR == DIR_UP && pad_getKey() == 0);
    SetFrameRun(1, 150);          // 回站姿
    break;
  ...
  default:                        // DIR_CENTER:沒推
    break;
}
```

- `do while` 條件放「搖桿還在這個方向、而且沒按其他按鍵」。一按按鍵就跳出,交給按鍵處理。
- 內層一定要呼叫 `custom_stickUpdate()`,否則方向變數不會更新,迴圈出不來。
- L3 / R3 也是 `switch (pad_getStickButtons())`,三個 `case`(只按 L3、只按 R3、兩個一起按),各有 `do while`,條件是 `pad_getStickButtons() == PAD_L3 && pad_getKey() == 0`。
- 每個 `case` 的 `break` 前,都預留了一行註解 `// SetFrameRun(1, 150);` 回站姿。

**L2 / R2 和左搖桿的組合:**
- **單純按 L2 或 R2** = 轉身(一個 `do while`,按住一直轉,放開回站姿)。
- **左搖桿往左 / 往右(單純推)** = 各有自己的動作,例如 `13`、`12`。
- **推左搖桿往左或往右的「途中」再按 L2 或 R2** = **只換掉其中一個動作**,其他照舊。例如單純往左是 `13`、`12`,加按 L2 就變成 `13`、`60`(動作 1 共用,動作 2 換掉)。左搖桿的左、右各有 3 種:單純、+L2、+R2。這段寫在 `custom_stickFun()` 的左搖桿 `DIR_LEFT` / `DIR_RIGHT`:

```cpp
case DIR_LEFT:
  do {
    SetFrameRun(13, 100);                    // 動作 1:單純和組合共用
    uint16_t k = pad_getKey();
    if (k == PAD_BTN_L2)      { SetFrameRun(60, 90); }   // 往左 + L2:動作 2 換成 60
    else if (k == PAD_BTN_R2) { SetFrameRun(61, 90); }   // 往左 + R2:動作 2 換成 61
    else                      { SetFrameRun(12, 90); }   // 單純往左:動作 2 照舊
    custom_stickUpdate();
  } while (LS_DIR == DIR_LEFT && stickKeyOkForCombo());
```

想換掉的是動作 1 而不是動作 2,就把 `SetFrameRun(13, 100)` 搬進 `if / else if / else` 裡,每個分支放不同的幀、動作 2 放到外面共用。

**順序有差:** 一定要**先推搖桿、再按 L2 / R2** 才會是組合動作。如果先按住 L2 / R2,程式已經在做轉身,搖桿不會被讀。

**程式是輪流執行,不是同時:** `custom_loop()` 每一圈依序跑 `custom_gamepadKeyFun_kondo()`(按鍵)→ `custom_stickFun()`(搖桿)→ 檢查電腦連線。沒動作時一圈約 10 ms;某一邊在做動作時,另一邊要等它做完。左搖桿的動作做的時候,右搖桿不會被讀。

### 教師密碼(有些功能不開放給學生)

**目前這個功能是關閉的:所有功能都開放,「設定」分頁也沒有「教師功能」區塊。** 程式還留著,之後要用再打開:把 `Tools_MotorAdj\MotorAdjPlus_src\License.java` 裡的 `ENABLED` 改成 `true`,重新編譯、打包 `MotorAdjPlus.jar`,再用 `%USERPROFILE%\MotorAdjPlus_teacher\set_password.bat` 產生 `pw.dat`。下面是啟用之後的說明。

**尚未在學生電腦上實測**(密碼驗證、猜錯鎖定、pw.dat 被改過或學生自己做一個、太短的密碼,都驗過;跳出密碼框的畫面沒有逐一點過)。

需要教師密碼才能用的功能:**送到機器人**(動作序列)、**批量載入幀**、**各馬達範圍…**、**路徑設定…**。**原版 `MotorAdj_release.jar` 的功能不在其中,沒辦法鎖**(它在同一個資料夾)。

- **怎麼用:** 按到被鎖住的功能時,會直接跳出密碼框,輸入正確就解鎖並繼續。也可以到「設定」分頁左下角的「教師功能」區塊按 **教師解鎖…** 先輸入。**解鎖到關掉 MotorAdj 為止**,下次打開要重新輸入;「鎖回去」可以馬上鎖上。猜錯 5 次要等 30 秒。
- **設定 / 更換密碼:** 老師的電腦執行 `%USERPROFILE%\MotorAdjPlus_teacher\set_password.bat`,輸入新密碼(輸入時看不到字,至少 6 個字),會產生新的 `Tools_MotorAdj\pw.dat`。**把新的 `pw.dat` 也放進學生的 `Tools_MotorAdj` 資料夾**,重開 MotorAdj 就生效。
- **密碼不是明文存的:** `pw.dat` 裡只有加鹽的雜湊,而且用老師的私鑰簽過章。學生改掉內容、或自己做一個 `pw.dat`,簽章不對,程式不接受,所以沒辦法換成自己的密碼。**刪掉 `pw.dat` 也不會解鎖**(沒有密碼檔就是鎖著)。
- **私鑰(最重要):** 在老師電腦的 `%USERPROFILE%\MotorAdjPlus_teacher\private.key`,**不在專案裡,不要上傳、不要給學生**。請另外備份一份。弄丟的話沒辦法再產生有效的 `pw.dat`;要重新產生一組金鑰、重新打包程式。
- **要知道的限制:**
  - **密碼要夠長、不容易猜**(建議 8 個字以上,不要用生日、1234 這類)。因為 `pw.dat` 在學生的資料夾裡,有心的學生可以拿去離線慢慢猜。
  - 密碼是全班共用的,只要有一個人知道(看到你輸入、問到),大家都能解鎖。懷疑洩漏就換一個密碼(上一步)。
  - Java 程式可以被反編譯,有心的學生有機會改掉檢查,這個機制擋的是一般情況。要更強的保護,可以改成「學生版 jar 根本不包含那些功能」。

**進階:綁定電腦的金鑰檔(可以不用)。** 老師的電腦上可以放一份綁定那台電腦的金鑰檔,開了就是已解鎖,不用輸入密碼:
  - 在要解鎖的電腦,「教師解鎖…」→「進階(金鑰檔)…」→「複製識別碼」,傳給老師。
  - 老師執行 `%USERPROFILE%\MotorAdjPlus_teacher\sign_key.bat`(單台)或 `sign_many.bat`(名單檔一次簽發全班),得到 `.key` 檔和 `MAP1-` 開頭的授權碼。
  - 對方在「進階(金鑰檔)…」按「匯入金鑰檔…」或「貼上授權碼…」。金鑰檔存在那台電腦的 `%APPDATA%\MotorAdjPlus\teacher.key`,不在專案資料夾裡,複製專案不會跟著過去。
  - 指令:`java -cp MotorAdjPlus.jar KeyTool sign|signmany|code|verify|setpw …`。

### 串口自動更新、批量匯出 / 載入幀

- **串口清單自動更新**:原版 MotorAdj 只在開啟時抓一次串口。現在每 2 秒會重新看一次,所以**先開咖啡杯、之後才插上 Micro 板**,「設定」分頁的串口下拉選單會自己多出來(拔掉也會消失)。你選的那個串口還在的話,選擇會保留。**連線中不會更新**,避免編號錯位。
- **批量匯出幀**:「馬達參數」分頁,「載入馬達幀」下面的 **批量匯出幀…**。先輸入**要匯出哪幾號幀**,例如 `3, 5, 10-12`(逗號分開,連續的用減號;輸入 `all` 是全部;幀號不存在或寫錯會提示重填),再選一個資料夾,每一幀存成一個檔:`frame_003.frame`、`frame_005.frame`…(格式跟原版單幀存檔一樣,是 JSON,用記事本打得開)。上次輸入的會記住,下次打開還在。
- **批量載入幀**:「儲存馬達幀」下面的 **批量載入幀…**。選哪幾個 `.frame` 檔就載入哪幾號(可複選),或選一個資料夾載入裡面全部。依檔案裡的幀號放進去:
  - 已有的幀會被覆蓋;幀號比現有幀數大的會自動新增(中間空出來的幀先複製最後一幀)。
  - **載入前會先把目前全部幀備份**到專案的 `backup\frames_before_import_日期時間\`,載錯了可以再用批量載入救回來。
  - 只要有一個檔案壞掉(缺馬達資料、沒有幀號),**整批都不會載入**,並告訴你是哪個檔。
  - 超過幀數上限(預設 90)會先警告。
  - 載入只是改 MotorAdj 目前的資料;要寫進機器人,還要「儲存設定」「轉換設定」「更新到機器人」。

### 機器人 3D(把 SolidWorks 的機器人放進咖啡杯,跟著馬達動)

**狀態:** 讀檔、3D 繪圖、伺服對照、結構運動學,都用你的真實模型(`robot_stl\`,84 個零件)在 Java 11 離線驗證過:每顆馬達單獨轉、雙馬達、腿的平行四邊形,渲染出來零件都沒有分離、穿幫;結構節點的平移量也和獨立算的公式一致。**還沒有和真實機器人對照過動作**(轉動方向正反、1 單位幾度,要靠你用實機確認)。只畫姿勢,**不做重力、碰撞、平衡**。

**這台機器人的結構(已經建好,存在 `robot_stl\rig.json`):**
  - 18 顆伺服馬達,每顆的轉軸位置與方向從零件形狀自動算出(用「伺服對照」指定它是第幾號馬達)。
  - **腿是雙平行四邊形連桿**:推動馬達(右 5、6;左 12、13)時,**膝蓋那塊整塊平移、不轉動**,腳掌始終跟大腿保持平行;曲柄板繞它的樞軸轉、假連桿板跟著平行轉。連桿孔位從零件上的圓孔自動量出,曲柄向量和假連桿向量精準相等(38.9, 38.9),所以動作是對的。
  - **右手臂**的肩膀(馬達 1 + 2)和手肘(馬達 3 + 18)各有兩顆並聯的馬達夾著同一個軸。3D 畫面**只看馬達 1 和馬達 3**,馬達 2、18 不影響畫面(並聯的另一顆,動作跟著前者)。
  - **左手臂**是四顆依序的馬達(8、9、10、22),**腰**(馬達 15)轉動上半身,**髖**(右 4、左 11、左 26)轉動整條腿,**腳踝**(7、14)轉腳掌。
  - 所以「零件指定」現在是指定給「結構節點」(例如「左膝蓋塊」),不是直接指定給馬達;「關節設定」只調每顆馬達的轉動方向、1 單位幾度、零位。
  - **改了馬達↔伺服的對照**(「伺服對照」),要重建結構:雙擊專案根目錄的 `重建機器人結構.bat`(會先把舊的 rig.json 備份成 rig.json.bak)。這個結構是針對這台機器人寫的,換成別的機器人要重新分析。

**怎麼對照實機(很重要):** 在「馬達參數」分頁拖某一顆馬達,同時看 3D 畫面和實機。如果某顆轉的方向和實機相反,到「關節設定」選那顆馬達,勾「轉動方向反過來」。「1 個單位 = 幾度」這台機器人實測 **550 單位 = 90°**,所以是 0.1636(±900 約 ±147°),已經設好;換別的伺服可以用「全部馬達用這個」一次改。

**1. 從 SolidWorks 匯出(只做一次)**
  1. 把完整機器人的組合圖擺成**所有馬達在 1500 的站姿**(程式以這個姿勢當零位)。
  2. 檔案 → 另存新檔 → STL → 選項:**取消**「把組合件的所有零組件儲存在單一檔案」(要每個零件一個檔)、**勾選**「不要把 STL 輸出資料轉換到正空間」(零件座標才會是組合圖的座標)、單位公釐。
  3. 輸出到專案的 `robot_model\` 資料夾。螺絲、小孔洞多的話,先用簡化配置或抑制掉,檔案小、畫面順。

**2. 載入**:「機器人 3D」分頁 →「模型與姿勢」→「載入模型資料夾…」(專案裡有 `robot_model\` 的話,第一次打開這個分頁會自動載入)。零件太多時會自動降面數,上限可調(改了要按「重新載入」)。模型的「上」是 Y 還是 Z 軸,不對就切換。

**3. 把零件指定給馬達**(「零件指定」小分頁)。每個零件由一顆馬達帶動;馬達轉的時候,它以及掛在它下面的關節的零件都會跟著動。
  - 3D 畫面:左鍵拖曳旋轉、右鍵(或 Alt+左鍵)拖曳平移、滾輪縮放、**點一下選零件**(Ctrl+點加選)、**Shift+拖曳框選**。也可以在清單裡搜尋、選取。
  - 選好零件 → 選一顆馬達 → 按「選中的零件 → 指定給這顆」。
  - **建議從離身體最遠的開始**(手掌、腳掌):先指定,再勾「隱藏已指定的零件」把它們藏起來,再框選下一段(前臂),這樣不會漏也不會選錯。「選取還沒指定的」可以檢查有沒有漏掉。
  - 身體(不動的部分)不用指定。

**4. 設定每顆馬達的關節**(「關節設定」小分頁)
  - **掛在哪顆馬達上**:例如手肘掛在肩膀那顆上(肩膀轉,手肘跟著動)。最靠近身體的馬達選「0 身體」。
  - **轉軸位置**:按「點 3D 設轉軸位置」再到畫面上點;或「點兩點取中點」(點轉軸孔的兩側);或選好零件按「用選中零件的中心」(例如選伺服馬達的輸出軸零件)。數字也可以直接改。
  - **轉軸方向**:按 X / Y / Z 或直接填,「反向」可以掉頭。
  - **轉動方向反過來**、**1 個單位 = 幾度**(預設 0.1636,這台機器人實測 550 單位 = 90° 換算來的,其他伺服要用實機對照校準;「全部馬達用這個」可以一次套用)、**零位**(預設 1500)。
  - 勾「**預覽這一顆**」,拖下面的滑桿,只有這顆轉,馬上看轉軸位置、方向、轉動方向對不對。
  - **左右對稱的馬達只要設一邊**:選「對面馬達」按「把這顆複製成鏡像」,轉軸位置和方向會對身體的左右對稱面鏡射、轉動方向自動反過來(同樣的馬達值會動出鏡像的動作)。複製完要預覽確認;零件指定和「掛在哪顆」要自己設。
  - 設定會自動存在模型資料夾的 `rig.json`(零件指定、26 顆馬達的關節),下次打開還在。

**5. 看機器人動**(「模型與姿勢」→「機器人姿勢跟著」)
  - 「**馬達參數**」目前畫面:拖捲軸、改數字,機器人跟著動。預設**不管有沒有勾「啟用」**都跟著動(「模型與姿勢」裡的「沒勾啟用的馬達也讓機器人跟著動」可以取消);還沒讀入幀、位置是 0 的馬達當作在零位。
  - 「**動作程式**」的模擬播放:在「動作程式」分頁按播放時,機器人跟著做動作。
  - 「**零位**」:全部 1500。
  - 設定關節時(「關節設定」分頁)一律用零位,點取的座標才是零位座標。

**限制**
  - 純 Java 自己畫,不需要額外程式庫;我測 12 萬個三角形約每秒 60 張,建議總數 6 萬以內。降面數是把相近的頂點合併,細節會變粗。
  - 畫的是「理想姿勢」:沒有馬達的慣性和負載、沒有重力、沒有碰撞(手臂會穿過身體都不會提醒),不能用來判斷機器人會不會跌倒。
  - 各馬達編號對應哪個關節,要你自己對照實機確認。

### 快速測試動作(馬達參數頁右上角)

**尚未實機驗證**(版面、沒連線和幀不存在的提示、送出的幀號順序、編輯中的資料不被動到,都用假的送出測過;「真的送給機器人」那一段沒有接機器人測過)。

「馬達參數」分頁右上角的 **快速測試動作** 區塊:讓機器人直接**去某一幀**,**不會動到你正在編輯的那一幀**(畫面上的數值、捲軸、按「寫入」的內容都不變),所以可以一邊調動作、一邊拿別的動作測穩定性。

- **A / B 兩個格子:** 各填一個幀號,按旁邊的 **去這一幀**,機器人就去那一幀。想來回測,就自己 A、B 交替按。
- **送的是已「寫入」的資料**(MotorAdj 目前載入的幀),不是畫面上還沒寫入的修改。所以如果你把 A 設成正在編輯的那一幀,要先按「寫入」,送出的才是你剛調的樣子。
- **要先:** 「設定」分頁按「串口連接」、按「開啟馬達」。沒連線、幀號不存在,都會在區塊下面那行提示,不會送。第一次送會跳出安全確認(機器人要架空或周圍安全)。
- **做法:** 跟「動作程式」分頁的模擬一樣,暫借工作區送指令、送完還原,所以不會改到你編輯中的內容(我測過,連送出失敗也會還原)。送出的那一瞬間(約 40 毫秒)請不要同時拖動馬達捲軸。

### 動作模擬(在「動作程式」分頁右邊,不用搖桿就能播出動作)

**尚未實機驗證**(展開、模擬播放、停止、沒連線時擋下來,都用 MotorAdj 的測試複本在 Java 11 測過;「真的送給機器人」那一段沒有接機器人測過)。

「動作程式」分頁現在分成兩半:**左邊是程式編輯**(跟以前一樣,上面選要修改的動作),**右邊是模擬**。左邊選哪個 case、你改了什麼(**還沒寫回 custom.ino 的修改也算,不用先寫入**),右邊按 **▶ 播放** 就播那一段:右上角的**機器人 3D 畫面會依時間做出動作**(模擬);勾選 **「送到機器人」** 的話,同時會**真的把每一幀送給機器人**,馬達會動。想隨手試幾個 `SetFrameRun`,直接在左邊的編輯框裡打、按播放就行(不按「更新到機器人」就不會寫回 custom.ino)。

- **右邊三塊:** 上面是**機器人 3D 模擬**(左鍵拖曳旋轉、右鍵平移、滾輪縮放;用的是「機器人 3D」分頁載入的模型和關節結構,已經不是長條圖了。專案裡沒有 `robot_stl` / `robot_model` 資料夾、還沒有模型時,才會退回顯示長條圖);**沒在播放時,3D 跟著「馬達參數」分頁目前的姿勢**(你在那邊拖捲軸、改數字,這裡也跟著動;按播放就從那個姿勢開始做模擬動作;播完會停在最後的姿勢,直到你又改了「馬達參數」)。左下「**實際會播的步驟**」是把左邊的程式展開後的結果(唯讀);右下「**播放記錄**」。播放中的那一行會在「實際會播的步驟」裡反白,錯誤訊息裡說的「第 N 行」也是這裡的行號。
- **怎麼展開:**
  - 「按住就重複」的迴圈(do while)會轉成 `repeat N`,輪數用「**迴圈輪數**」設定。
  - 有「如果有按著 L2…」之類的判斷時,用「**按著的組合鍵**」選要模擬哪個鍵;判斷結果會寫成註解。搖桿方向、L3/R3、自訂條件一律當作成立。
  - 只有 `SetFrameRun(幀, 毫秒)`、`delay(毫秒)`、重複、如果/否則會被模擬,其他程式碼(例如 `custom_stickUpdate()`)略過。
  - 動作被註解掉的模板、或幀編號用名稱(例如 `IMU_CROUCH_FRAME`)的行,播放前會被標成錯誤。左邊內容不是 `case …:` 開頭(看不懂)時,按播放會提示。
- **模擬速度:** 很短的動作(例如 20 毫秒)肉眼看不到,可以選「慢 2/5/10 倍」。只影響畫面模擬,「送到機器人」一律原速。
- **用哪些幀:** MotorAdj 目前載入的幀資料(「馬達參數」分頁「寫入」過的),不是燒進 Micro 的 `motor.h`。兩邊要一致,播出來才跟機器人實際跑的一樣。
- **按鈕:** **▶ 播放**、**■ 停止**、**單步**(一次播一步,看每一步)、**循環播放**、**放鬆全部馬達**(緊急用:馬上停止播放,並把所有馬達放鬆)。
- **送給機器人要先:** 「設定」分頁按「串口連接」、「馬達參數」分頁按「開啟馬達」。沒連線就勾「送到機器人」,會擋下來並提醒。第一次送會跳出安全確認(機器人要架空或周圍安全、手要隨時可以按停止)。
- **模擬的畫法:** 播到一幀時,有啟用的馬達從目前位置,用那一幀的「速度」欄位的時間走到目標位置;沒啟用的馬達不動(跟 Micro 的 `SetFrameRun` 一樣)。這是理想情況,實際馬達有慣性、有負載,會慢一點。
- **和 Micro 自己跑的差別(重要):** 從電腦逐顆送指令,**每一幀大約要 40 毫秒**,Micro 自己播一幀只要幾毫秒。所以很短的時間(例如 20 ms)會被拉長(播放記錄會註明)。另外,真的用搖桿時,迴圈是按住就一直重複、放開才停,還有手把資料每 100 毫秒才送一次的延遲、IMU 補償等,模擬都沒有。這個功能適合看**動作順序和大致節奏**,不適合量精準時間。
- **安全:** 送出時會暫時借用「馬達參數」分頁的工作區(`MotorPosDataTmp`),送完立刻還原,不會影響你在「馬達參數」分頁正在編輯的內容(我測過,連送出失敗也會還原)。

### PS4 手把燈條(顏色表示狀態)

**尚未實機驗證**(Micro 端已編譯通過;ATOM 端的燈條程式我這邊編譯不了,請你在 Arduino IDE 驗證後再燒)。

- **多接一條線:Micro 的 D9 → ATOM 的 G32**(Micro 把感測器狀態回報給 ATOM)。沒接這條也能操作,只是燈條會一直閃黃。
- **顏色:**
  - **ATOM 自己的燈(Atom Lite 上那顆):** 手把還沒連上**閃黃色**;手把連上就**恆亮**,顏色跟手把燈條一致(黃 = Micro 還沒回報、藍 = 沒感測器、綠 = 有感測器),比手把的暗一點。
  - 手把還沒連上:**ATOM 自己的燈閃黃色**(手把這時還不受我們控制)。
  - 手把已連上,但 Micro 還沒回報(沒接線 / 還在開機):**手把燈條閃黃色**。
  - 已連上,Micro 有偵測到 BNO055:**綠色**;沒有偵測到:**藍色**(沒接感測器就一直是藍色,按 Options 不會變色)。
  - 想改成「按 Options 把傾斜感測開啟才綠色」:ATOM 程式的 `LED_GREEN_WHEN_ENABLED` 改成 1。
- **電量:** 按手把的 **PS 鍵**,燈條顯示電量 3 秒(綠 = 夠、黃 = 一半、淺紅 = 偏低、深紅 = 快沒電),之後回到上面的顏色。電量原始值會印在 ATOM 的序列監控(`Battery raw=…`),百分比的換算是我估的,若不準可以對照原始值調整。
- **震動(手把):** 連上手把約 1 秒後**震一下**;傾斜感測**開啟震一長下、關閉短短兩下**(Micro 回報的狀態改變時);電量低於約 15%(燈條深紅那段)且沒在充電時,**每 20 秒短短兩下**提醒。強度、門檻、間隔在 ATOM 程式的 `RUMBLE_STRENGTH`、`LOW_BATT_PCT`、`LOW_BATT_REMIND_MS`。**尚未實機驗證。**
- **按住就震:** 按住 **圈圈、方塊、R1、L1** 任何一顆,手把會**持續震動,放開就停**(Share / Options 不算)。輕輕的細震,強度在 ATOM 程式的 `HOLD_SMALL`(小馬達,預設 70)、`HOLD_LARGE`(大馬達,預設 0 = 不用),滿是 255,按住的鍵可以改 `HOLD_RUMBLE_KEYS`。事件震動(連上、切換、低電量)優先,結束後如果還按著,會接著繼續震。**尚未實機驗證。**
- **怪資料防護(ATOM):** 手把剛連上、或閒置後,函式庫偶爾會把「不是正常輸入的封包」解讀成亂按的鍵和推到底的搖桿。ATOM 現在只接受開頭是 `A1 11` 的正常報告,其他丟掉,並且連上後要收到第一筆正常報告、再過 0.5 秒才開始送資料(之前送「什麼都沒按」)。序列監控每秒會印一行 `DIAG reports/s=… bad=…`(`bad` 是被丟掉的封包數),查完可把 `DIAG_PRINT` 設成 0。**尚未確認能完全解決閒置怪資料,需要實機觀察。**


### 傾斜感測(BNO055):被推、被打時自己修正

**尚未實機驗證**(只通過編譯,還沒接感測器和機器人測試)。

- **接線:** BNO055 的 SDA、SCL、GND、電源接到板子上綠色的 I2C 接頭(SDA = D2、SCL = D3)。沒接感測器時程式照常運作。
- **開關:** 按 PS4 的 **Options** 切換「傾斜感測」開 / 關(序列監控會印 `IMU ON / OFF`)。每次進入遙控模式一開始是關。Options 本來就是「回站姿」,所以按一下會同時回站姿並切換。
- **只在你沒操作時才介入:** 有按任何鍵、推搖桿、按 L3/R3 時完全不干涉,放開後穩定 1.5 秒才開始偵測。
- **怎麼修正:**
  1. 在 MotorAdj 錄一幀「浮誇的修正姿勢」,**只勾選要動的馬達**(例如大腿)。前後傾、左右傾各錄一幀。
  2. 到 `custom.ino` 的傾斜感測區塊,把 `IMU_PITCH_FRAME`、`IMU_ROLL_FRAME`、`IMU_CROUCH_FRAME` 的 `-1` 換成幀編號(`IMU_STAND_FRAME` 預設 1)。
  3. 傾斜愈大,姿勢就從站姿愈往浮誇姿勢混過去,動的速度也愈快;往另一邊倒則反向。傾斜超過 `IMU_CROUCH_DEG`(預設 35 度)就直接做蹲下的動作。
  4. `IMU_DEAD_DEG`(死區 5 度)、`IMU_FULL_DEG`(20 度達 100%)、`IMU_SLOW_MS` / `IMU_FAST_MS`(動作時間)可以自己調。
- **第一次測試:機器人一定要架空,先用小幅度的姿勢確認方向。** 方向反了會讓機器人往更倒的方向動;往前倒卻變成往後,改 `imu.ino` 的 `IMU_PITCH_SIGN` / `IMU_ROLL_SIGN`(`-1`)。
- 空間:75 幀約 86%、90 幀約 94%。

## 通訊協定(進階)

ESP32 每 100 ms 送一次 10 個位元組,鮑率 38400:

```
0xAA, 0x55, 按鍵低, 按鍵高, LX, LY, RX, RY, 按下搖桿(L3=bit0, R3=bit1), checksum(前 9 個位元組 XOR)
```

搖桿值 = 實際值 + 128(0~255);checksum = 前 9 個位元組 XOR。開頭是兩個位元組 `0xAA 0x55`(只用一個 `0xAA` 的話,手把完全沒動時檢查碼剛好是 `0xAA`,接收端一旦錯位一個位元組就會「剛好合法」而永遠卡住,所以加了 `0x55`,而且檢查碼不對時會從下一個位元組重新找開頭)。
按鍵位元值定義在 `Micro_Robot/pad.h`(與舊 Kondo 遙控器的值相同)。
間隔 100 ms 是刻意的:Micro 播放動作時不讀資料,`SoftwareSerial` 緩衝區只有 64 位元組,送太快會溢位。

## 常見問題

| 現象 | 檢查 |
|---|---|
| 手把連不上 | MAC 是否寫進手把、是否為原版 ESP32、core 是否 2.0.x |
| ESP32 序列埠有 `key=` 但機器人沒反應 | 共地、G26 → D8 接線、Micro 是否已燒錄新程式 |
| 按 Options 沒反應 | 從機器人上電到按 Options 之前,確認 ESP32 已經連上手把 |
| 機器人動作亂跳 | 電源不足;伺服馬達與 ESP32 建議用穩定的電源 |
| 編譯錯誤 `IcsSoftSerialClass.h` | 使用了舊的 `範例` 資料夾,請改用 `HumanoidRobot_PS4/Micro_Robot` |

```bash
git status                      # 看哪些檔案改過
git diff                        # 看改了什麼

git log --oneline               # 看歷史版本
git checkout -- Micro_Robot/custom.ino            # 把這個檔案退回最近一次存的版本
git checkout <版本代號> -- "Tools_MotorAdj/hurtmaker light.config"   # 把動作資料退回某個舊版本
```
