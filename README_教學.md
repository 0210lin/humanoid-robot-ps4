# 人形機器人 PS4 遙控改裝教學

把原本的 Kondo 遙控器換成 PS4 手把。

```
PS4 手把 ──藍牙──> ESP32 ──UART(TX→pin 8)──> Arduino Micro ──Serial1(500000)──> 伺服馬達
```

## 資料夾說明

| 資料夾 | 用途 |
|---|---|
| `Micro_Robot/` | 燒錄到 **Arduino Micro** 的主程式(已整理) |
| `ESP32_PS4_Bridge/` | 燒錄到 **ESP32**,讀 PS4 手把並送給 Micro |
| `ESP32_GetMAC/` | 一次性小工具:查 ESP32 的藍牙 MAC |
| `Tools_MotorAdj/` | 原本的馬達調整工具(電腦端,需要 Java) |

### Micro_Robot 內的檔案
| 檔案 | 作用 | 要不要改 |
|---|---|---|
| `custom.ino` | **按鍵 → 動作**、**搖桿 → 動作**對照表 | 想改動作就改這裡 |
| `motor.h` | 所有動作幀資料(由 MotorAdj 產生) | 用 MotorAdj 產生,不要手改 |
| `pad.ino` / `pad.h` | 從 ESP32 收按鍵與搖桿、按鍵位元定義 | 一般不用改 |
| `Micro_Robot.ino` | 馬達通訊、電腦通訊協定 | 一般不用改 |
| `custom.h` | 函式宣告 | 不用改 |

整理內容:移除所有 Kondo 專用程式、I2C 手把、感測器、計時器與永遠不會執行的 `mode 2`,Micro 程式佔用 77%(加入搖桿功能後;再省空間的最大一塊是 `motor.h` 的動作幀資料,約 11.5 KB,只能靠減少幀數)。`custom.ino` 加上中文註解,動作邏輯與原本相同。

---

## 第 0 步:確認硬體

- **M5Stack ATOM Lite**(ESP32-PICO-D4,有傳統藍牙,可配對 PS4 手把)。
- Arduino Micro 已經在你的電路板上。
- 三條線:

| ATOM Lite | 你的電路板 (PCB X1 mini) |
|---|---|
| Grove 接頭的 **G26**(看 Grove 線的顏色:通常白線 = G26,黃線 = G32,請用三用電表或對照 M5Stack 官方圖確認) | **DIO 排針的 D8** |
| GND | DIO 排針的 GND(**一定要共地**) |
| 5V | DIO 排針的 5V(給 ESP32 供電;若電流不夠或不穩,改用 USB 另外供電) |

Micro 不需要回傳資料給 ESP32,所以 ESP32 的 RX 不用接。
請**不要**使用板子的 4 pin「UART 接頭」,它是 Micro 的硬體 Serial1,已被伺服馬達通訊佔用。原本 Kondo 接收器用的 D8、D9、D4 在 DIO 排針上,現在空出來了。

## 第 1 步:安裝軟體

1. 安裝 **Arduino IDE 1.8.19** 或 **2.x**(arduino.cc/en/software;1.8.19 在下方 Legacy IDE,選 ZIP 解壓縮即可,可與舊版並存)。舊的 1.8.4 不建議,裝不了 ESP32 套件。
2. ESP32 支援:「檔案 → 偏好設定 → 額外的開發板管理員網址」加入
   `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
   然後「工具 → 開發板 → 開發板管理員」搜尋 **esp32** 安裝 **2.0.17**(**不要用 3.x**,PS4 函式庫在 3.x 上有問題)。
3. 安裝 PS4Controller 函式庫:到 `github.com/aed3/PS4-esp32`,下載 ZIP,
   「草稿碼 → 匯入程式庫 → 加入 .ZIP 程式庫」。
4. Micro 這邊不需要額外函式庫(舊的 `IcsSoftSerialClass` 已移除),`SoftwareSerial` 是內建的。

## 第 2 步:查 ESP32 的藍牙 MAC

1. 開啟 `ESP32_GetMAC/ESP32_GetMAC.ino`。
2. 工具 → 開發板選 **M5Stack-ATOM**,選好 COM 埠,上傳。
3. 開啟序列埠監控視窗(115200),記下 `ESP32 Bluetooth MAC: xx:xx:xx:xx:xx:xx`。

## 第 3 步:讓 PS4 手把記住 ESP32

PS4 手把只會連到它記住的「主機」。要把 ESP32 的 MAC 寫進手把:

1. 下載 **SixaxisPairTool**(Windows 小工具;網路上搜尋即可,安裝驅動時請留意來源)。
2. 用 USB 線把 PS4 手把接上電腦,開啟工具。
3. 在 Master 欄輸入第 2 步的 MAC,按 **Update**。
4. 拔掉線。

## 第 4 步:燒錄 ESP32 橋接程式

1. 開啟 `ESP32_PS4_Bridge/ESP32_PS4_Bridge.ino`。
2. 把 `#define PS4_MAC "aa:bb:cc:dd:ee:ff"` 改成你的 MAC。
3. 開發板選 **M5Stack-ATOM**,上傳。
4. 開序列埠監控視窗,按手把中間的 **PS 鍵**,手把燈會變成穩定亮。按按鍵時會看到 `key=0x.... stickBtn=0x..`(一般按鍵與 L3/R3 分開顯示)。

> 若沒有連上:確認 MAC 一致、手把電量足夠、Arduino core 是 2.0.x。

## 第 5 步:燒錄 Micro

1. 開啟 `Micro_Robot/Micro_Robot.ino`。
2. 開發板選 **Arduino Micro**,選好 COM 埠,上傳。
   (Micro 的 pin 0/1 是硬體 Serial1,和 USB 分開,上傳時不需要拔線。)
3. 接好第 0 步的三條線。
4. 開 Micro 的序列埠監控視窗(115200),手把連線後每 200 ms 會印一行,例如:
   `key=0x1 LX=0 LY=95 RX=-3 RY=0 L3=0 R3=0`
   用來確認按鍵、搖桿、L3/R3 的數值都正確。要關閉,把 `pad.h` 的 `PAD_DEBUG_PRINT` 改成 0。
   (接上電腦用 MotorAdj 時不會印,不影響它。)

## 第 6 步:操作

1. 機器人上電,ESP32 與 Micro 都會開機。
2. 按 PS 鍵讓手把連線。
3. 按 **Options** = START,機器人進入遙控模式並回站姿。
4. 按鍵對照:

| PS4 | 原 Kondo | 動作 |
|---|---|---|
| ↑ | UP | 前進 |
| ↓ | DOWN | 後退 |
| → / ← | RIGHT / LEFT | 右轉 / 左轉 |
| ✕ | CROSS | 幀 35→36 |
| ○ | CIRCLE | 幀 23→24 |
| □ | SQUARE | 幀 25→26 |
| L1 / R1 | L1 / R1 | 幀 29→30 / 27→28 |
| L2 / R2 | L2 / R2 | 按住時同時判斷搖桿:左搖桿往上、右搖桿往上、都沒往上(原本的動作)。往上的動作目前是註解 |
| **Options** | START | 開始 / 回站姿 |
| **Share** | STOP | 馬達全部放鬆 |

按住方向鍵會持續走,放開會自動回站姿。

蘑菇頭(搖桿)、L3/R3、L2/R2 搭配搖桿的動作目前**都是註解,尚未綁定**(範例在 `custom.ino`),見第 7 步。

安全機制:ESP32 與 Micro 之間超過 0.3 秒沒收到資料,Micro 會當作「沒有按鍵」,動作會停止。手把斷線也是同樣情形。

## 第 7 步:修改 / 新增動作

- **改動作姿勢**:雙擊 `Tools_MotorAdj/MotorAdjPlus.jar`(咖啡杯圖示,需安裝 Java)。它就是原本的 MotorAdj,只是在「馬達參數」分頁、「轉換設定」按鈕正下方多了一顆 **「更新到機器人(燒錄)」**:
  1. 照平常調整動作,按「轉換設定」輸出 `motor.h`(存在 `Tools_MotorAdj` 資料夾,或直接選存到 `Micro_Robot\motor.h` 都可以)。
  2. 按「更新到機器人(燒錄)」。它會自動:中斷串口連線 → 備份舊的 `motor.h` 並複製新的 → 編譯 → 燒錄到 Arduino Micro,過程顯示在跳出的小視窗。
  3. 看到「完成」後,按 MotorAdj 的「串口連接」重新連線,繼續調整。
  - MotorAdj 不用關,可以一直開著。原本的 `MotorAdj_release.jar` 沒有修改,仍可照舊使用。
  - 只有 `Tools_MotorAdj\motor.h` 比 `Micro_Robot\motor.h` 新時才會複製,所以直接輸出到 `Micro_Robot` 的不會被蓋掉。
  - 不開 MotorAdj、只想把目前的 `motor.h` 燒進去時,可以雙擊 `一鍵更新動作.bat`。
  - 外掛的原始碼在 `Tools_MotorAdj/MotorAdjPlus_src/Plus.java`。
  - `MotorAdjPlus` 另外修正了「關閉馬達」:按下去只會把馬達關閉(畫面也顯示成關閉),**不會把「關閉」寫進該幀的資料**。之後按「讀出」,就會把該幀原本的設定讀回來並恢復動作。(只有用 `MotorAdjPlus.jar` 開啟才有這個修正,原本的 `MotorAdj_release.jar` 仍是舊行為。)
  - **「動作程式」分頁(在「馬達偏移量」旁邊):直接改 Arduino 的動作與延遲時間。**
    1. 切到「動作程式」分頁,上方的下拉選單會列出 `custom.ino` 裡每個 `switch` 的每個 `case`(按鍵、按下搖桿 L3/R3、左搖桿方向、右搖桿方向),例如「按鍵 › case PAD_BTN_UP」。
    2. 選一個,下面就會顯示**從 `case` 到結尾的整段程式**,可以直接改(例如把 `SetFrameRun(2, 100)` 的 100 改成別的延遲時間)。改過的項目前面會有 ●。
    3. 改完按「更新到機器人(燒錄)」(這個分頁和「馬達參數」分頁各有一顆,功能相同)。它會:把修改寫回 `Micro_Robot\custom.ino`(舊版先備份到 `backup`)→ 編譯 → 燒錄。
    4. 如果**編譯失敗**,`custom.ino` 會自動還原成修改前的樣子,你的修改還留在分頁裡,修正後再按一次即可。
    - 「重新載入 custom.ino」:重新讀檔(也會放棄還沒寫入的修改);「還原這一段」:把目前這段改回檔案裡的原樣。
    - 這裡只能改 `case` 內的內容;`case` 之外的程式(例如迴圈最後的 `delay(10)`)要直接改 `custom.ino`。
    - 同一時間可以改好幾段,一起按一次更新就會全部寫入。
  - **「路徑設定…」按鈕**(「馬達參數」分頁、「載入設定」正下方;「動作程式」分頁最上面一列也有):可以設定
    1. **Arduino 程式資料夾**(裡面有 `custom.ino`、`motor.h`)
    2. **motor.h 來源**(MotorAdj 輸出的那個檔)
    3. **arduino-cli 位置**
    4. **序列埠**(留空 = 自動偵測 Arduino Micro;有多塊板子時可以指定,例如 `COM7`)

    欄位**預設是空白,空白 = 自動**(依資料夾位置推算),視窗下方會顯示目前實際使用的位置。按「儲存」後設定會存在 `Tools_MotorAdj/MotorAdjPlus.properties`,下次開啟自動套用,不用每次重設。「還原預設」會把欄位清成空白。
  - **沒有變動就不上傳:** 每次成功上傳後,會記住當時程式資料夾(`custom.ino`、`motor.h` 等)的內容指紋(存在 `MotorAdjPlus.properties` 的 `lastUpload`)。下次按「更新到機器人」時,如果內容和上次上傳的一樣,就直接略過編譯與上傳,只顯示「沒有變動,不用重新上傳」(這種情況視窗不會自動關閉;只有上傳成功時才會自動關閉)。**要強制重新上傳:按住 Shift 再按按鈕。**(換了一塊板子、或用別的方式燒錄過時,請用 Shift 強制上傳一次。)
  - **鏡像功能(左右對稱的動作):**
    1. 到「**鏡像**」分頁(最右邊),按「新增配對」,設定哪兩顆馬達左右鏡像。每一列有:**啟用**、**馬達 A**、**馬達 B**(編號 = 畫面上的 Ch 編號)、**方向**、**模式**。設定會自動存起來(`MotorAdjPlus.properties`),下次開啟還在。
       - **方向:** 同向 = 位置照抄;反向 = 以 1500 為中心反轉(新位置 = 3000 − 對方的位置)。偏掉的部分用「馬達偏移量」調整。
       - **模式:** 互換 = A、B 對調;A→B = 只有 B 變成 A 的鏡像;B→A = 只有 A 變成 B 的鏡像。啟用與時間(速度)會一起帶過去。
       - **單顆自己鏡像:** A、B 選同一顆、方向選「反向」,這一顆會自己左右反轉。
    2. 到「馬達參數」分頁,先「讀出」你要鏡像的那一幀,按左下角的 **「鏡像(畫面)」** 按鈕。畫面上這一幀的參數(連機器人連著時馬達也會動)就會依設定變成鏡像。
    3. **不會寫入。** 滿意的話,自己輸入要存的幀編號,再按原本的「寫入」。不滿意就再按「讀出」還原。
    - 同一顆馬達不要出現在兩組啟用的配對裡(會提示並且不做任何修改)。鏡像後的位置會被限制在馬達位置的最小、最大值之內。
  - **外觀:** MotorAdjPlus 預設用現代扁平風格(圓角按鈕、藍色重點色,「開啟馬達」為綠色、「關閉馬達」為紅色)。在「路徑設定…」視窗最下面的「**外觀**」可以切換 **淺色(預設) / 深色 / 原本的樣子**,按「儲存」立刻生效並記住。外觀用的是 [FlatLaf](https://www.formdev.com/flatlaf/)(Apache 2.0 授權),檔案在 `Tools_MotorAdj/MotorAdjPlus_lib/flatlaf-3.7.2.jar`;這個檔案被刪掉的話,會自動維持原本的外觀,不影響功能。
  - **自訂背景:** 到「**設定**」分頁(串口連接那一頁),左下方的 **「背景…」** 按鈕。把 **JPG / PNG / GIF / BMP 圖片直接拖進**跳出的視窗,或按「選擇圖片…」,上方會**即時預覽**,同時主視窗也會跟著變。
    - **圖片遮罩**滑桿:越高圖片越淡、文字越清楚(預設 75%);0% = 完全看到圖片。圖片會自動放大蓋滿整個視窗。
    - 也可以只選**純色**背景(「選擇純色…」)。「清除圖片 / 清除純色」可以拿掉。
    - 按「確定」才會儲存並記住;按「取消」或關閉視窗會還原成開啟前的樣子。
    - 選到的圖片會**複製一份**到 `Tools_MotorAdj/background` 資料夾,原檔之後刪掉、搬走都不會影響背景。換圖、清除時舊的副本會自動刪掉。
    - 背景可以跟淺色 / 深色外觀搭配,遮罩會跟著外觀換顏色。
    - **圖片比例不同怎麼辦:** 「背景設定」視窗裡有 **顯示方式**:**蓋滿視窗**(預設,會裁掉多出來的部分)、**完整顯示**(整張都看得到,兩側或上下會留邊,留邊顏色用「選擇純色」設定)、**拉伸填滿**(會變形)。另外有 **縮放**(100~300%)、**水平位置**、**垂直位置** 滑桿,也可以**直接在預覽上用滑鼠拖曳**移動圖片、**滾輪縮放**,決定要留圖片的哪一塊。換新圖時位置與縮放會自動回到預設;「重設位置與縮放」可以手動回到預設。
  - **馬達捲軸微調:** 「馬達參數」分頁每顆馬達的捲軸,**左右兩端各有一顆「-」「+」按鈕**,按一下 **±10**,**按住不放會連續移動**;**點捲軸中間的空白軌道一次 ±100**。這兩個數字可以在畫面左側的「捲軸微調」修改(「-」「+」按鈕:± 1 / 5 / 10 / 20 / 30;點空白軌道:± 10 / 20 / 30 / 50 / 100 / 200),會記住。馬達沒啟用(捲軸是灰色)時,按鈕也是灰色、按不動。
  - **復原 / 重做「寫入」:** 「馬達參數」分頁「寫入」按鈕旁邊有 **「← 復原」** 和 **「重做 →」**。每次按「寫入」之前,MotorAdjPlus 會先把那一幀目前存的內容記下來。不小心按到「寫入」時,按「← 復原」就會把那一幀**還原成寫入之前的樣子**(畫面也會切到那一幀);復原之後又後悔,按「重做 →」可以**再往前**回到剛才的內容。可以連續來回多次(最多記 100 次);做了新的「寫入」之後,「重做」會清空(跟一般的復原重做一樣)。沒有可復原或可重做的內容時,按鈕是灰色的。注意:紀錄只存在記憶體,**關掉 MotorAdj 就清空**;只處理「寫入」,不包含「儲存設定」等其他動作。
  - **人偶模式(用手擺姿勢、自動讀角度):** 按「馬達參數」分頁的「人偶模式」,每顆馬達旁邊會出現一個**圓點**。選一顆,那顆就是「人偶」(放鬆中,可以用手擺),畫面上它的數值會即時更新成實際角度;選下一顆,前一顆會鎖在你擺好的位置。全部擺好後,輸入幀編號按「寫入」存成一幀;再按一次「人偶模式」離開。
    - **MotorAdjPlus 修正了畫面:** 原本一按「人偶模式」,所有馬達的勾選框會被取消、捲軸整排變灰,看起來像「全部放電」,但**實際上並沒有送任何指令給機器人**(馬達還有力)。現在進入人偶模式時會**維持原本的勾選與藍色捲軸**,並把**被選為人偶(放鬆中)的那顆馬達的勾選框標成橘色**,一眼看出現在哪顆是軟的。(只有用 `MotorAdjPlus.jar` 開啟才有這個修正。)
    - **離開人偶模式時**,MotorAdj 會把「畫面上記錄的姿勢」整組重新送給機器人,所以機器人會回到畫面資料的姿勢,不一定是你用手擺的姿勢。想保留手擺的姿勢,**離開之前先「寫入」成一幀**。
    - 使用時請先扶好機器人(或讓它躺著、架空),被選到的那顆會放鬆,可能因為重力下垂。
  - **快速新增幀:** 「馬達參數」分頁**左下角**(「捲軸微調」的上方)有一顆 **「+ 新增幀(60/100)」**(括號是目前幀數 / 上限)。按一下,在最後多一幀,內容**複製畫面上目前這一幀**,並自動切到那一幀讓你編輯(改完按「寫入」)。
    - 新增後要記得 **「儲存設定」**(幀數會存進設定檔的 `mmax`)和 **「轉換設定」**(輸出新的 `motor.h`),然後按「更新到機器人」。
    - **Arduino 程式不用改**:`motor.h` 裡的 `MOTOR_FRAME_MAX` 會自動跟著變(用 MotorAdj 實際輸出的 65 幀 `motor.h` 放進去編譯驗證過)。
    - **限制是 Micro 的程式空間:** 每幀約佔 156 位元組。74 幀約 79%;加到 100 幀約 93%,還剩約 1.9 KB 給你之後寫的呼叫與邏輯。超過約 112 幀就放不下,所以**幀數上限預設 100**,超過時會先警告。上限可以在 `MotorAdjPlus.properties` 加一行 `frameLimit=120` 修改(要先確認空間夠)。
  - **幀編號檢查(「動作程式」分頁底部):** 分頁底部有一行「幀編號:…」,會掃描 `custom.ino` 裡所有 `SetFrameRun(幀編號, …)`(**包含還沒寫入的修改**,被 `//` 註解掉的不算),並和 Arduino 的 `motor.h` 幀數比對:
    - **綠色**:所有編號都存在,並顯示用到幾幀、有幾幀完全沒被用到。
    - **橘色**:MotorAdj 有這一幀,但 Arduino 的 `motor.h` 還沒有 → 要先「轉換設定」,再「更新到機器人」。
    - **紅色**:這一幀不存在 → **機器人會默默忽略那個動作,不會有任何錯誤提示**,所以特別需要這個檢查。
    - 按「詳細…」會列出每個有問題的編號(在哪個 `case`),以及「完全沒被用到的幀」(例如 `0、18~22、31~34`),之後想省 Micro 空間時,就知道哪些可以刪。
  - **「設定」分頁右下角的三張卡片:**
    1. **機器人狀態:** 有沒有偵測到 Arduino Micro(和序列埠)、MotorAdj 的串口有沒有連線、**程式同步狀態**(已同步 / 有尚未上傳的變更:會列出是 custom.ino、motor.h 或「動作程式」分頁的修改)、上次上傳時間、檔案修改時間。
    2. **Micro 空間用量:** 程式空間與記憶體的用量長條(用最近一次編譯的結果,按過一次「更新到機器人」後才有數字)、目前幀數,以及「加到上限幀數後」預估的空間用量與剩餘。超過 85% 變橘色、95% 變紅色。
    3. **環境檢查:** Java、arduino-cli、Arduino AVR 支援、程式資料夾、Micro 序列埠,正常是綠色、缺少是紅色並提示執行「安裝.bat」。按「重新檢查」可以重測。
    - 這個分頁顯示時才會定時更新,不會在背景一直跑。
  - **給別人用:** 把整個 `HumanoidRobot_PS4` 資料夾複製過去,先雙擊 **`安裝.bat`**。它會檢查並自動安裝:Java(用 winget)、arduino-cli(從 downloads.arduino.cc 下載,約 25 MB)、Arduino AVR 板子支援(`arduino-cli core install arduino:avr`)。已經有的會略過,需要網路。完成後雙擊 `Tools_MotorAdj/MotorAdjPlus.jar` 即可。資料夾結構不同時,用上面的「路徑設定…」指定。
- **改按鍵對應**:編輯 `custom.ino` 的 `custom_gamepadKeyFun_kondo()`,例如改 ✕ 鍵播放另一組幀:
  ```cpp
  case PAD_BTN_CROSS:
    SetFrameRun(35, 100);      // 先播這一幀,等 100ms
    do {
      SetFrameRun(36, 20);     // 按住時重複播這一幀
    } while (pad_getKey() > 0);
    SetFrameRun(1, 150);       // 放開後回站姿
    break;
  ```
- 接上電腦用 MotorAdj 時,機器人會自動離開遙控模式。

### 搖桿(蘑菇頭)

**三組資料互相獨立**,互不影響:

| 組 | Micro 讀取 | 內容 |
|---|---|---|
| 一般按鍵 | `pad_getKey()` | 方向鍵、○✕□△、L1/R1/L2/R2、Options、Share |
| 推搖桿 | `pad_getStick(PAD_LX / PAD_LY / PAD_RX / PAD_RY)` | -128 ~ 127,Y 向上為正 |
| 按下搖桿 | `pad_getStickButtons()` | 回傳 `PAD_L3`、`PAD_R3`、兩個相加,或 0 |

`custom.ino` 的 `custom_stickFun()` 每圈迴圈會執行一次,裡面已經寫好範例,**動作都是註解**(`// SetFrameRun(1, 100);`),要用時把 `//` 拿掉並換成你的幀編號。組合鍵已全部移除(PS4 用不到),只保留 START、STOP。

**每支搖桿有兩組判斷**(`LS_` 開頭 = 左搖桿,`RS_` 開頭 = 右搖桿,1 = 是,0 = 不是):

| 組 | 變數 | 意思 |
|---|---|---|
| 半邊 | `LS_UP`、`LS_DOWN`、`LS_LEFT`、`LS_RIGHT` | 往那個方向推過死區就是 1。斜推時相鄰兩個會同時是 1(右上 = `LS_UP` 和 `LS_RIGHT`)。`LS_UP` 就是「上半邊」。用 `if` 判斷,R2 / L2 也用這個 |
| 單一方向 | `LS_DIR`、`RS_DIR` | 同一時間只有一個,值是 `DIR_CENTER` / `DIR_UP` / `DIR_DOWN` / `DIR_LEFT` / `DIR_RIGHT`。斜推時哪個軸推得多就算哪個。給 `switch` 用 |
| 沒推 | `LS_CENTER`、`RS_CENTER` | X、Y 都在死區內 |

死區大小用 `STICK_DEAD` 調整(預設 60,範圍 0~127,愈大愈要推多一點才算)。

**單推搖桿用 `switch (LS_DIR)`,每個方向一個 `case`,連續動作放 `do while`:**

```cpp
switch (LS_DIR) {
  case DIR_UP:
    do {
      SetFrameRun(幀A, 100);      // 動作 1
      SetFrameRun(幀B, 90);       // 動作 2
      custom_stickUpdate();       // 一定要有,不然出不來
    } while (LS_DIR == DIR_UP && pad_getKey() == 0);
    SetFrameRun(1, 150);          // 回站姿
    break;
  ...
  default:                        // DIR_CENTER:沒推
    break;
}
```

- `do while` 條件放「搖桿還在這個方向、而且沒按其他按鍵」。一按按鍵就跳出,交給按鍵處理。
- 內層一定要呼叫 `custom_stickUpdate()`,否則方向變數不會更新,迴圈出不來。
- L3 / R3 也是 `switch (pad_getStickButtons())`,三個 `case`(只按 L3、只按 R3、兩個一起按),各有 `do while`,條件是 `pad_getStickButtons() == PAD_L3 && pad_getKey() == 0`。
- 每個 `case` 的 `break` 前,都預留了一行註解 `// SetFrameRun(1, 150);` 回站姿。

**R2 / L2 搭配搖桿:** 按住 R2 或 L2 時,每一圈同時讀左、右搖桿:

```cpp
if (LS_UP)      { do { 動作1; 動作2; custom_stickUpdate(); } while (pad_getKey() > 0 && LS_UP); }
else if (RS_UP) { do { 動作1; 動作2; custom_stickUpdate(); } while (pad_getKey() > 0 && RS_UP); }
else            { 原本 R2 / L2 的動作(也是 do while) }
```

兩支搖桿同時往上時,只會做左搖桿的。這個寫法假設你不會同時推兩支搖桿。

**程式是輪流執行,不是同時:** `custom_loop()` 每一圈依序跑 `custom_gamepadKeyFun_kondo()`(按鍵)→ `custom_stickFun()`(搖桿)→ 檢查電腦連線。沒動作時一圈約 10 ms;某一邊在做動作時,另一邊要等它做完。左搖桿的動作做的時候,右搖桿不會被讀。

## 通訊協定(進階)

ESP32 每 100 ms 送一次 9 個位元組,鮑率 38400:

```
0xAA, 按鍵低, 按鍵高, LX, LY, RX, RY, 按下搖桿(L3=bit0, R3=bit1), checksum
```

搖桿值 = 實際值 + 128(0~255);checksum = 前 8 個位元組 XOR。
按鍵位元值定義在 `Micro_Robot/pad.h`(與舊 Kondo 遙控器的值相同)。
間隔 100 ms 是刻意的:Micro 播放動作時不讀資料,`SoftwareSerial` 緩衝區只有 64 位元組,送太快會溢位。

## 常見問題

| 現象 | 檢查 |
|---|---|
| 手把連不上 | MAC 是否寫進手把、是否為原版 ESP32、core 是否 2.0.x |
| ESP32 序列埠有 `key=` 但機器人沒反應 | 共地、G26 → D8 接線、Micro 是否已燒錄新程式 |
| 按 Options 沒反應 | 從機器人上電到按 Options 之前,確認 ESP32 已經連上手把 |
| 機器人動作亂跳 | 電源不足;伺服馬達與 ESP32 建議用穩定的電源 |
| 編譯錯誤 `IcsSoftSerialClass.h` | 使用了舊的 `範例` 資料夾,請改用 `HumanoidRobot_PS4/Micro_Robot` |
