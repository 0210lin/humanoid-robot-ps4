# ServoID 模組:用手機編伺服馬達 ID

換馬達時,把新馬達插在模組上,用手機(iPhone / Android 都行,不用裝 App)連模組的 WiFi,開網頁就能:
**掃描 → 改 ID → 讀回確認 → 測試轉動**,然後直接裝回機器人。

> **狀態:韌體已寫好、能編譯、封包格式已用 PDF 和原廠工具的範例驗證;電路和韌體都還沒有在真的硬體上測試過。**
> 第一次請照下面「第一次通電」的順序做,先用一顆**不要的馬達**。

## 選哪塊 ESP32

| 板子 | 用途 | 編譯目標 | 腳位(TX / RX / 電池偵測) |
|---|---|---|---|
| **M5Stack ATOM Lite** | 麵包板原型(目前在用) | `esp32:esp32:m5stack-atom` | G22 / G19 / G33 |
| **ESP32-C3 SuperMini**(約 22.5×18 mm,2.54 mm 排針孔,USB-C,便宜) | **最後做成一塊板子,最好焊** | `esp32:esp32:esp32c3:CDCOnBoot=cdc` | GPIO7 / GPIO6 / GPIO3,LED = GPIO8 |
| Seeed XIAO ESP32-C3 | 也可以 | `esp32:esp32:XIAO_ESP32C3:CDCOnBoot=cdc` | D5 / D4 / D1 |

- 做成一塊板子時,建議用 **ESP32-C3 SuperMini**:它的腳是一般 2.54 mm 間距的排針孔,可以直接焊在洞洞板或自己的電路板上,不用處理貼片。
- **注意**:SuperMini 有些批次的 WiFi 天線效果比較差,訊號距離會短,但貼著手機用沒問題。要用之前建議先用一片測試 WiFi 連線是否穩定。
- 裸的 ESP32 模組(貼片)比較難手焊,不建議。
- 三種板子是同一份韌體,編譯時依晶片自動選腳位。

## 接線

> 電路圖:[`schematic.svg`](schematic.svg)(向量圖,可放大)/ [`schematic.png`](schematic.png)。下面的文字圖是簡化版,**以電路圖為準**。

```
電池 XT60 +  ──[保險絲]──┬────────────────────→ 馬達接頭「電源」針(紅)
                           └→ 降壓模組 IN+
電池 XT60 −  ───────────────┬──────────────────→ 馬達接頭「Gnd」針(黑)
                            └→ 降壓 GND ── XIAO GND

降壓 OUT+(5V) ─[1N5819]─→ XIAO 5V 腳
降壓 OUT+(5V) ─[1N4148]─[3.3kΩ]─┬─→ Sig 節點 = 馬達接頭「Sig」針(白)
                                   │
                  BAT54 陽極 ───────┤   BAT54 陰極 → XIAO D5(GPIO7,TX)
                                   │
                          22kΩ ────┘→ XIAO D4(GPIO6,RX) ──47kΩ── GND

電池分壓:電池 + ─100kΩ─ XIAO D1(GPIO3) ─22kΩ─ GND
```

腳位(韌體編譯時依晶片自動選):

| | XIAO ESP32-C3 | **M5Stack ATOM Lite** |
|---|---|---|
| 匯流排 TX(接 BAT54 陰極) | D5(GPIO7) | **G22** |
| 匯流排 RX(接 Sig 分壓) | D4(GPIO6) | **G19** |
| 電池電壓偵測 | D1(GPIO3) | **G33**(ADC1,WiFi 開著也能量) |
| 供電 | 5V 腳 | **5V 腳**(從降壓模組的 5 V 接進來) |
| LED | 板上 D10 | G27 全彩 LED(匯流排有動作時亮青色) |

ATOM Lite 的 G22、G19、G33 在底部排針上,**請對照板子上的絲印確認**(我是依 M5Stack 的腳位圖,沒有拿到實物)。要改腳位,改 `ServoID_Module.ino` 最上面。

**原理(單線 UART)**:匯流排平常被上拉到高電位;送資料時 TX 拉低,二極體導通把匯流排拉低,TX 為高時二極體截止,由上拉維持高電位;接收則把匯流排經分壓降到 ESP32 能承受的電壓(Sig 4.1 V → RX 約 2.8 V)。單線會聽到自己送出的資料(回音),韌體會先讀掉,並檢查回音是否正確(不正確 = RX 接線有問題)。

## 燒錄

**M5Stack ATOM Lite**(先用它做原型):
```
Tools_Arduino\arduino-cli.exe board list                                  找出 ATOM Lite 的 COM 埠
Tools_Arduino\arduino-cli.exe compile --fqbn esp32:esp32:m5stack-atom ServoID_Module
Tools_Arduino\arduino-cli.exe upload  --fqbn esp32:esp32:m5stack-atom -p COM你的埠 ServoID_Module
```

**XIAO ESP32-C3**:
```
Tools_Arduino\arduino-cli.exe compile --fqbn esp32:esp32:XIAO_ESP32C3:CDCOnBoot=cdc ServoID_Module
Tools_Arduino\arduino-cli.exe upload  --fqbn esp32:esp32:XIAO_ESP32C3:CDCOnBoot=cdc -p COM你的埠 ServoID_Module
```

**只想先測 WiFi 和網頁**:不用接任何外部電路,燒錄後 ATOM 只靠 USB 供電就會開 WiFi,手機連上去能開網頁(電池會顯示「沒接電池」,掃描會找不到馬達,這是正常的)。

開機後序列監控(115200)會印 `[自我檢查] 封包格式 全部 PASS` 和 WiFi 熱點名稱。

## 手機操作

1. 手機 WiFi 連 **ServoID-XXXX**,密碼 **servoid1234**(韌體裡 `AP_PASS` 可改)。iPhone 會說「沒有網路」,不用理它。
2. 瀏覽器開 **http://192.168.4.1**。
3. **步驟 1(最重要)**:先只接電池、**不要插馬達**。網頁顯示電池電壓和 2S / 3S。選你要編的馬達是 7.4 V 還是 12 V,**電池和選的電壓不符時網頁會用紅字警告**,這時絕對不要插馬達。
4. 確認相符後才插馬達。
5. **掃描**:找出馬達現在是幾號。只找到 1 顆才能改 ID。
6. **改 ID**:選新號碼 → 按按鈕。韌體會寫入、等 1.5 秒、讀回確認,並檢查舊 ID 已經消失。
7. **測試轉動**:馬達要空載(不掛任何東西)。會往中點方向小幅轉動再回來,並讀回位置確認。
   **微調 −100 / +100**:每按一次動 100 單位(約 16°),以第一次按時的位置當原位,最多離原位 ±100;「回原位」可以回去。電池電壓和選的馬達不符時這些按鈕會鎖住。
8. 電池電壓不準時校正:用三用電表量電池,瀏覽器開 `http://192.168.4.1/api/cal?v=實測電壓`(例如 `?v=7.52`)。

## 第一次通電(請照順序)

1. **只接 USB**(沒電池、沒馬達):手機能連上 WiFi、網頁打得開。序列監控看到自檢 PASS。
2. 降壓模組**單獨**接電池,用三用電表量輸出,調到 **5.0 V**。調好才接到 XIAO。
3. 接電池(不接馬達):網頁電壓應該接近你三用電表量到的值;不準就用 `/api/cal` 校正。
4. 用三用電表量 **Sig 對 Gnd** 的空閒電壓,應該約 **4.0~4.2 V**(你原廠轉接板量到 4.2 V)。差太多先不要插馬達。
5. 插一顆**不要的馬達**:掃描 → 應該找到 1 顆。
6. 讀狀態、測試轉動、改 ID、再掃描確認。
7. 都正常再拿來編要上機器人的馬達。

## 安全設計

- 韌體**永遠不會送廣播(ID 0)的寫入指令**(`servobus.h` 裡 ID 0 會被拒絕,開機自檢也會檢查)。
- 改 ID 前先掃描 1~127:找到的馬達不是剛好 1 顆就拒絕。
- 測試轉動只有在「電池電壓和你選的馬達電壓相符、電量不低」時才允許;位置夾在 800~2200(PDF 的有效範圍);角度只有 100~250 單位(約 16~41°)。
- **模組不能切斷馬達電源**:電池是直通馬達的。插錯電池(例如 12 V 接到 7.4 V 的馬達)馬達就會直接承受,韌體擋不住。所以**一定要先接電池看電壓,確認後才插馬達**。

## 已知限制 / 沒驗證的

- 電路(上拉 3.3 kΩ、分壓 22 kΩ / 47 kΩ、單二極體送出)在 500000 baud 下的波形夠不夠乾淨,**要實測**(最好用示波器)。不夠的話改用電晶體做開集極輸出,TX 腳用 `uart_set_line_inverse` 反相。
- 「讀 ID 暫存器」的回應格式是依 PDF 推論的(寫 ID 的封包是從原廠工具程式取得);讀回失敗時先用原廠工具確認馬達狀態。
- 電壓、電流、溫度暫存器只顯示原始值(0~1023),換算係數我不知道。
- 沒有做「輸出功率上限」:暫存器位址 4 在 PDF 裡是可寫的,但原廠工具沒用它,我沒驗證,所以不敢放進韌體。
- 預設 WiFi 密碼寫死在韌體裡,只適合在自己手邊使用。

## 檔案

- `ServoID_Module.ino`:主程式(WiFi、網頁 API、掃描、改 ID、測試)
- `servobus.h`:封包產生(純 C++,ID 0 一律拒絕)
- `webpage.h`:手機網頁

## 協定來源

- ServoBus protocol V0.5 PDF
- 原廠 `CAS_Servo_Management` 工具(用靜態分析讀出的封包):
  - Ping:`[ID|0x80] 81 [CS]`
  - 改 ID:`[目前ID|0x80] 92 20 00 [新ID] [CS]`(位址 32,值的低位元組 = ID)
  - 設位置:`[ID|0x80] 83 05 位置高 位置低 時間高 時間低 [CS]`,放鬆 = 位置 0
  - 讀暫存器:`[ID|0x80] 91 長度 位址 [CS]`(位置 5、電壓 7、電流 8、溫度 9、ID 32)
  - 檢查碼 = 前面所有位元組相加取低 8 位元,500000 baud 8N1,結尾沒有 0xFF
